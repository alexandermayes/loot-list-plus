# Local development

Run LootList+ against a fully local Supabase, with a seeded test guild, without
touching production.

## Prerequisites

- A container runtime (Docker Desktop, OrbStack, or Colima) running.
- The [Supabase CLI](https://supabase.com/docs/guides/cli) installed.
- Project dependencies installed (`npm install`).

## One-command setup

```bash
npm run db:local:seed
```

This:

1. Starts the local Supabase stack (`supabase start`).
2. Rebuilds the schema from the baseline migration and seeds global reference
   data (`supabase db reset` → applies `supabase/migrations/` + `supabase/seed.sql`).
3. Creates test users and seeds a test guild with characters, submissions, and
   loot history across the Classic and TBC phases.

Tunables: `USERS` (default 8), `GUILDS` (1), `MEMBERS` (20), e.g.
`GUILDS=2 MEMBERS=30 npm run db:local:seed`.

## Run the app against local

```bash
npm run dev:local      # next dev on :3100, wired to the local stack (PORT to override)
```

Then open <http://localhost:3100/dev-login> and use a **quick-login** button.
`loadtest1` (the first one) is a Guild Master, so officer-only views (Master
Sheet, Raid Tracking → Loot history, loot management) are available.

> Only one `next dev` runs per project directory. If a production-pointed
> `npm run dev` is already running, stop it first.

## How it works / maintenance

- **Schema** comes from `supabase/migrations/20260101000000_baseline_schema.sql`
  (the baseline; see `supabase/migrations/README.md`).
- **Reference data** (`wow_classes`, `class_specs`) lives in `supabase/seed.sql`,
  generated by `npm run gen:seed` (reads the linked prod project). Re-run that if
  the reference data changes.
- The seeders target local because `npm run db:local:seed` exports the local
  Supabase credentials before invoking them; the `.env.local` loader won't
  clobber already-set vars.
- `loadtest/test-users.json` and `loadtest/user-guild-map.json` are generated
  per run and gitignored.

Nothing here reads or writes the production database except `npm run gen:seed`
(read-only, only when you choose to regenerate reference data).

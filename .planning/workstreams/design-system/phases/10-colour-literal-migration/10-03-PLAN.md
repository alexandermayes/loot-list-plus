<objective>
Create the quality and brand colour constants as a single source of truth in two places that cannot drift -- a TypeScript module for JS/TS consumers and five named Tailwind colour keys for class consumers -- then migrate every Tailwind arbitrary-value hex class in this phase's scope onto the named keys, and stand up the parity guard.

Purpose: plan-time classification found that D-12's TS-constants mechanism only covers 19 of the 34 hex lines. The other 15 are Tailwind arbitrary-value classes, and a Tailwind class built by interpolating a constant never generates any CSS at all. This plan resolves that with the mechanism this repo already ships for its 13 WoW class colours -- named `theme.extend.colors` keys with raw hex values -- and proves the two representations agree structurally rather than by convention.

This plan does the class sites. The 19 JS/TS data sites and the COLOR-05 absence guard are 10-05.

Output: the constants module, the five Tailwind keys, 15 (or 14) migrated class sites, and the parity guard.
</objective>

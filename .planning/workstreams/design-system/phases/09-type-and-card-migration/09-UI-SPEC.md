## Typography

This phase's job is the **mapping rule**, not new type roles. The existing alias scale (shipped Phase 07) already defines Body/Label/Heading; this phase adds eight display-size aliases (D-01) and mechanically routes ~932 arbitrary `text-[Npx]` sites onto the nearest existing or new alias. No new semantic role is introduced.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 13–16px (`base`/`md`/`lg` aliases) | inherited per-site, unchanged | 1.5 |
| Label | 11–12px (`xs`/`sm` aliases) | inherited per-site, unchanged | 1.5 |
| Heading | 18–32px (`xl`–`4xl` aliases) | inherited per-site, unchanged | 1.2 |
| Display | 28–80px (new D-01 aliases: `text-28`, `text-40`, `text-44`, `text-48`, `text-56`, `text-64`, `text-72`, `text-80`) | inherited per-site, unchanged | 1.2 (28/40/44/48) or 1.02 (56/64/72/80), per D-04 |

This phase does not change any font-weight; the codemod only touches font-size classes and never a font-weight class.

**Named accepted deltas (locked, not open questions — must be listed by file at the plan's checkpoint per CONTEXT.md's specifics):**
- **D-02:** `text-[17px]` (one site: `LandingLootDecision`) rounds up to `text-18`. `text-[22px]` (one site: `PremiumItemTooltip`) rounds up to `text-24`. No `text-17` or `text-22` alias exists or should be created.
- **D-03:** The two `text-[8px]` sites in `app/(app)/master-sheet/components/BossSection.tsx` (the "tied" chip and the gap number) rise to `text-11`, the TYPE-01 floor. This is a visible, intentional change on the master sheet.
- **D-04:** ~51 heading-sized sites (18px–80px) with no existing `leading-*` class will visibly tighten from inherited 1.5 to the alias's line-height (1.2, or 1.02 at 42px+). This is accepted as the scale's intent, not a bug — do not pin these with `leading-normal` to preserve the old spacing. They must be listed by file at the checkpoint and reviewed in the screenshot gate.
- Sites at 16px and below are unaffected — the alias line-height (1.5) matches the browser-inherited default, so no visible delta there.

**Executor guardrail:** the codemod (`scripts/codemods/text-sizes.mjs`, D-15) is the single source of truth for the pixel→alias mapping via its committed JSON table — this table above must match that JSON exactly. If they diverge, the JSON wins and this document should be corrected, not the reverse.

## Color

**Unchanged by this phase.** Colour-token migration is Phase 10's scope (COLOR-03 through COLOR-07); Phase 09 touches no colour value. The table below documents current, already-shipped (Phase 07) values purely for context — Card's background/border/text colours pass through unchanged when its base radius changes.

| Role | Value (light / dark) | Usage |
|-------|-------|-------|
| Dominant (60%) | `--background` #faf8f5 / #09090c | Page background |
| Secondary (30%) | `--background-elevated` (= `--card`) #ffffff / #1d1f25 | Cards, elevated surfaces — this is the surface `Card` and every migrated hand-rolled card paint |
| Accent (10%) | `--accent` #e67300 / #ff8000 | Reserved for: primary CTAs, active/selected states, focus indicators that use `--ring`. Not touched by this phase. |
| Destructive | `--destructive` (unchanged, per Phase 07 OI-3) | Destructive actions only. Not touched by this phase. |

Accent reserved for: primary call-to-action buttons, active nav/tab state, focus-visible rings (`--ring`), and the accent-text token (`--accent-text`) already wired to `text-accent` uses. This phase introduces and changes none of these; listed here only so the checker does not flag omission.

**Card surface tokens relevant to D-06/D-10 (unchanged, cited for context):**
- `--card` equals `--background-elevated` exactly in both themes, so swapping a hand-rolled `bg-background-elevated` string for `Card`'s `bg-card` class paints pixel-identical.
- `--border` (default divider/card border) and `--border-strong` (emphasis divider, e.g. `SettingsModal`, `GuildSettingsContent`) are both unchanged; D-08 preserves the `border-border-strong` distinction on migrated sites that carry it today.
- The existing divider idiom `border-t border-border` (59 uses today) is what the new `nested` variant (D-10) reuses — no new colour token, no new border colour.

## Card Primitive Contract (this phase's actual deliverable — supplementary to the template)

Since this phase's core work is a primitive contract change plus a mass migration, the following is recorded precisely because the template's generic sections don't have a dedicated slot for it:

### `Card` base changes (D-06, D-11)
- Base class string changes from `rounded-lg border border-border bg-card text-card-foreground` to `rounded-xl border border-border bg-card text-card-foreground` — only the radius utility changes.
- `CardVariant` union extends from `"default" | "unified"` to `"default" | "unified" | "nested"`.
- For `variant="nested"`: base surface classes (background, border, radius) are switched off entirely. The only class applied is the divider: `border-t border-border`. No separate `CardSection` export; no alias component.
- Padding on `nested`, exactly like `default` and `unified`, passes through via `className` — the variant does not impose its own padding.

### Radius delta scope (D-06)
- 136 of 149 exact-string hand-rolled cards already draw 12px radius (`rounded-xl` equivalent) — these become pixel-identical once migrated.
- 13 `rounded-lg` hand-rolled sites, plus cards in 11 files that already `import { Card }` (`sheet-import`, `admin/addon`, `admin/analytics`, `reserve`, `reserve/runs/[id]`, `design-system`, `dev-login`, `ExpansionGuard`, `guild-select/discord-join`, `reserve/join/[token]`, `SettingsModal`), gain 4px of radius (8px → 12px) as a visible, named delta — every such site must be listed at the checkpoint.

### Hand-rolled card detection contract (D-08, D-13) — what the guard and codemod treat as "a card"
- A hand-rolled card = any class string containing `bg-background-elevated`, a `rounded-*` utility, AND either `border-border` or `border-border-strong`, in any order (order-independent regex).
- `border-border-strong` sites keep their emphasis: `<Card className="border-border-strong ...">`.
- Excluded from both sweep and guard: ~29 lines with `bg-background-elevated` + `rounded-*` but no border token (pills, wells, inputs) — inventoried, not migrated.
- Excluded from this phase's guard specifically: the 5 card-shaped `bg-background-inset` lines — Phase 10's guard widens to catch these when it removes that token (D-13).
- `bg-card` one-offs outside `card.tsx`: Claude's Discretion whether to treat as a synonym of `bg-background-elevated` (if they carry both a border token and a radius) — reported at the checkpoint either way.

<objective>
Make `components/ui/modal.tsx`'s `Modal` a real ARIA dialog end to end — `role="dialog"`,
`aria-modal="true"`, an accessible name wired from `ModalTitle` through a new id-context, a
hand-rolled focus trap, focus return on close, and stacking-aware Escape handling that only the
topmost simultaneously-open Modal installs — per CONTEXT.md D-03/D-04/D-05. Then give the three
modals that currently render no title (`JoinGuildModal`, `OnboardingModal`, `UpgradeModal`) one.

This is the phase's only net-new logic (no focus-trap library exists anywhere in the repo, and
`Modal`'s current 312 lines have no `role`/`aria-modal` anywhere) and its riskiest edit, so it
lands before the label/focus-ring/skeleton plans in the same phase, per 08-01-PLAN.md's
checkpoint-approved batching order ("Modal first").

Purpose: `Modal` backs every dialog in the app (10+ call sites); getting its accessibility
contract right once, with a real vitest test proving it, is what lets every later modal-touching
plan in this milestone trust the primitive instead of re-verifying it.
Output: `components/ui/modal.tsx` extended in place; `components/ui/__tests__/modal.test.tsx`
(new file, new directory); three previously title-less modals each gain a `ModalTitle`.
</objective>

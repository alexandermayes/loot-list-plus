<objective>
Close G-11-1: make the app's numerals actually render tabular, and prove it by measuring rendered glyph advances rather than by reading the CSS back.

Purpose: `app/globals.css` declares `font-variant-numeric: tabular-nums` on `.tabular-nums`, 86 sites across 19 files apply that class to loot scores, score-breakdown lines, attendance percentages, ranks and prices, and the declaration computes correctly on every one of them -- and changes nothing, because Poppins ships no `tnum` feature. 11-UAT.md measured 42 to 49 percent per-digit width variance at all four shipped weights and 13.49px of jitter between `11.1` and `88.8` at weight 600, against a system-ui control that measured 0px with the identical property. The defect is a font capability gap, already diagnosed empirically; this plan does not re-diagnose it.

The approach is locked by user sign-off on 2026-09-21 (11-UAT.md `decided_approach`): the numerals class gains its own `font-family` from a self-hosted, tnum-capable face while Poppins stays the prose and UI font. Smallest blast radius, no brand-level change.

The second purpose is the reason this gap existed at all. Phase 11's verification treated the emitted rule as proof and routed only the visual half to UAT, so a provably inert declaration passed a gate. This plan ships the measurement that gate was missing, proves it red against the current code before anything is fixed, and makes it the acceptance criterion -- not a supplement to one.

Output: a reusable rendered glyph-advance probe, a screened and user-chosen numeral face wired through the existing next/font pipeline, a cascade-robust family declaration, a regression tripwire, and an evidence record that names every residue it did not fix.
</objective>

**The cascade note, which is load-bearing.** Tailwind emits its own `tabular-nums` utility into `@layer utilities`, and every Tailwind family utility lands there too. Cascade layers beat specificity: a `font-family` declared for the numerals class inside `@layer base` or `@layer components` loses to any family utility on the same element, unconditionally. Zero call sites collide today, so a layered rule would pass this plan's own probe and then go inert the first time someone adds a family utility next to the class -- which is the exact shape of the defect being closed. Put the family declaration in the unlayered tail of `app/globals.css`, following that file's own existing precedent at line 403 (`ICON/LOGO ADAPTIVE THEMING (outside layers for higher specificity)`), and say why in the comment.

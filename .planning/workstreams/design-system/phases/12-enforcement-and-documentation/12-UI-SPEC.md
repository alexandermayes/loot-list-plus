# Phase 12 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase shape note (read this before the tables below).** Phase 12 is almost entirely non-UI: ENF-01 (`DESIGN.md`) is a markdown file, ENF-02 (`.impeccable/config.json`) is JSON config, and ENF-04/ENF-05 are blocked on a deploy (`12-CONTEXT.md` D-01) and out of this phase's scope entirely — no contract is written for them. Every fact below was grep-verified live against the 2051-line file during this research session, not assumed from the roadmap's prose.

## ENF-03 Docs Page Contract (supplementary — this phase's actual deliverable)

Per D-10/D-12, each item below is a **live example plus a short caption**, not a restated value table. Exact numeric values are never hand-typed into this page's JSX going forward — they live in `DESIGN.md` and the page points to it. Internal mechanism (how an example reads a token without duplicating its value — computed style, CSS variable, or just rendering the real primitive) is Claude's Discretion per `12-CONTEXT.md`; what follows specifies *what* must be shown and *what the caption must say*, not the JSX mechanism.

### 1. Type scale (fixes a live defect in TWO places, not just an addition)

This page hand-types a pixel size next to `text-xs` in **two independent clusters**, and both currently claim **10px** where `tailwind.config.js` has read **11px** since Phase 07's TYPE-01. Every other hand-typed size on the page (text-sm through text-5xl, in both clusters) is correct today — this is a single wrong value, duplicated in two places, not a pattern to go hunting for elsewhere.

- **Cluster A — the Type Scale table (`_client.tsx:382-398`):** remove the hand-typed `size: '10px'` / `'42px'` / etc. strings entirely. Show the rendered example and its Tailwind class name only (e.g., `text-5xl font-bold`) — no pixel number in the row.
- **Cluster B — the `Text` component "Sizes" preview (`_client.tsx:429-436`):** remove the hand-typed `(16px)` / `(14px)` / `(13px)` / `(12px)` / `(10px)` parentheticals from each `<Text size="...">` example's label text — show the rendered example and its `size` prop value only (e.g., `Tiny` next to a visible `size="xs"` example), no pixel number appended. This cluster's labels come from the `Text` component's own size props, not a hand-authored array like cluster A, so whatever mechanism removes cluster A's numbers must also suit a component-prop preview here — the exact JSX shape is the planner's call, not this document's.
- **Both clusters:** per D-10, the fix is *removing* the hand-typed number, not correcting it to `11px` — writing the corrected value by hand re-creates the identical rot the next time the token changes. Point to `DESIGN.md` instead (see the shared caption below).
- **Add** the `text-15` step, currently entirely absent from cluster A's list, between the `text-base` and `text-lg` rows (Phase 07's TYPE-01 added it as a new step between 13px and 16px; it is not a Phase 12 decision — `12-CONTEXT.md`'s D-02 is about recording blocked requirements and has nothing to do with the type scale).
- **Add** one caption sentence, placed once, visible to a reader of either cluster (below the Type Scale table, or wherever the planner judges most legible for both): *"Exact pixel values for every step, including the pixel-named and display aliases, are in `DESIGN.md` § Typography."* — this single sentence is what documents the pixel-named (`text-11`…`text-42`) and display (`text-28`…`text-80`) aliases; do not enumerate all 19 of them here.
- **Add** one sentence to the existing "Label Text" subsection (`_client.tsx:461-476`, already correctly describes the `LabelText`→`Text` consolidation) tying it explicitly to the form-field `Label` primitive shown in Form Inputs above it: *"This is the app's only label convention: `Label` for form fields, `Text` for section headings. `LabelText` and `.section-label` were removed in Phase 08."* This closes the "single Label" half of criterion 3 — it is a one-sentence connective fix, not a new example, because the actual `Label` and `Text` usages are already demonstrated elsewhere on the page.
- **Leave line 468 alone** (`"12px, not uppercase (was 10px uppercase pre-migration)"`) — the "was 10px" there is legitimate migration history, not a stale current-value claim, and is out of this item's scope.

### 2. Reading measure (`.prose-measure`, 0 hits today)

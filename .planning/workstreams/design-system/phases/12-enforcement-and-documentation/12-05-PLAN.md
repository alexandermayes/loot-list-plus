## Hook mechanics this plan relies on (read from source at plan time)

- Wiring: `.claude/settings.local.json` runs `hook.mjs` on `PostToolUse` (matcher `Edit|Write`) and `Stop`. `hook.mjs` routes a stdin event with `hook_event_name: "Stop"` to `runStopHook`, anything else to `runHook`. Both write one JSON line to stdout shaped `{"hookSpecificOutput":{"hookEventName":...,"additionalContext":"<text>"}}` and always exit 0.
- Tiering: PostToolUse surfaces only `IMMEDIATE_TIER_RULES` (`hook-lib.mjs:113-131`: includes all four `design-system-*`, `low-contrast`, `tiny-text`; excludes `side-tab`, `ai-color-palette`, `pulsing-dot`, `numbered-section-labels`). Stop runs the full rule set over files the session touched, deduplicated against what PostToolUse already surfaced for that session.
- Finding lines read `- L<line> [<rule-id>] <name>. <description> If intentional: \`ignore-value <rule> <value>\`.` (`formatFindingLine`, `hook-lib.mjs:1143`).
- Caps: `limits.maxFindings` 5 and `maxChars` 8000 per emission (`DEFAULT_CONFIG`); `maxFileBytes` 131072 (all probe targets measured under it; `LootListContent.tsx` is closest at 117,689 bytes). `readConfig` merges `.impeccable/config.json` then `.impeccable/config.local.json`; the local file is excluded from git by `.git/info/exclude`.
- Audit: with `IMPECCABLE_HOOK_LOG` set, each invocation appends one NDJSON record (`findings`, `freshFindings`, `emitted`, `skipped`, `scannedFiles` on Stop).
- Config reach: an `ignoreValues` entry with value `*` requires `files`; a value-bearing entry without `files` applies everywhere (`impeccable-config.mjs:455-481`). File globs also match any trailing path-segment suffix of a finding's file, which is how a rendered-URL finding could be scoped by page path.
- The detector CLI gives remote http(s) targets no design system (`cli/main.mjs`), so the local rendered run can never produce `design-system-*` findings.

<objective>
Fix GH #484: Import BIS ignores the officers' class prio list and can drop an item prio'd to other classes into Bracket 1 (an officer saw a hunter with a tank neck at rank 50 on a new TBC Anniversary list).

Purpose: the editor already stops raiders from picking or dragging out-of-prio items into Brackets 1-4 and No Bracket. Import BIS is the one editor path that skips that rule, because `importBisItems` places items by classification, item_type, item_slot and allocation_cost only. Moving the pool rule into one pure function and gating the import with it closes the hole without changing how anything else behaves.

Output: `domain/loot/prio-zones.ts` (the rule), `domain/loot/bis-import-placement.ts` (the import placement loop, now testable without React and gated by the rule), their tests including a regression for #484, and the two editor files calling them. Code lands on `fix/bis-import-respects-prio` in three atomic commits; nothing is pushed.

- GH-484: the reported bug.
- PRIO-R1: pure zone rule in domain/loot with unit tests on every branch.
- PRIO-R2: editor pools use the rule; membership and order byte-identical.
- PRIO-R3: import gates Brackets 1-4 on 'bracket' and No Bracket on 'noBracket'; lock seeding unchanged.
- PRIO-R4: regression test marked for #484 that fails before the fix.
- PRIO-R5: no new user-facing copy; a skipped-for-prio count is a follow-up needing owner copy sign-off.

- DELIVERY-R1: own code branch from origin/main, atomic commits, gates run and counts reported, back on the gsd/quick branch before SUMMARY.md.

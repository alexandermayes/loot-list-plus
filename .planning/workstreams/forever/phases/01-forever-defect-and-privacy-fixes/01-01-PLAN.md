## Assumptions and Flagged Items

If a real night times out, the fallback is `after()` for the raid_event_id branch only; record any observed latency in SUMMARY.
- A8 (from RESEARCH, unchanged): other `loot_history` deletion paths (raid event deletion cascade, `user/delete-account`) are not audited for BLP here; outside FIX-01's wording. Flagged as a follow-up, not silently dropped.
- A9 (new, planning): `MAX_AUDIT_PAYLOAD_BYTES` is compared with `JSON.stringify(...).length`, which counts UTF-16 code units, not bytes, so a receipt with non-ASCII names can hold somewhat more than 4096 bytes. The E-11 boundary tests pin the existing unit; switching to a byte count is outside FIX-04 and not planned.
- E-04 (concurrency) is authored as a backstop truth: the verifier confirms it by reading `recompute_blp_for_item` and `recomputeBlpForItems`, and abstains to human_needed if it cannot.

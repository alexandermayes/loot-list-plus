# Phase 4: UI Design Contract

> Visual and interaction contract for Phase 4 (Discovery Lists and Score Split). Generated by gsd-ui-researcher, verified by gsd-ui-checker. Every user-facing string in this file is DRAFT copy for the owner's sign-off. No em dashes or en dashes anywhere in user-facing text.

Sources pre-populated: `04-CONTEXT.md` D-01 to D-27 (locked, not re-opened), `.planning/research/FEATURES.md` (five-row proposal, feature 8), `DESIGN.md`, `lib/design-system/`, `components/ui/*`, and the surfaces read in the codebase. | Property | Value |

## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Icon to label gap, gap between meter segments, badge inner padding |
| sm | 8px | Gap between sheet tiles, gap between stacked rows, helper text offset, icon to text gap inside a row (`gap-2`), ScoreSplit tile padding (`p-2`) and the Total column offset (`pl-2`) |
| md | 16px | Card padding on phone (`p-4`), page side padding on phone, sticky footer padding, gap between picker sections |
| lg | 24px | Card padding from `sm` up (`sm:p-6`), gap between the header block and the rows |
| xl | 32px | Gap between major blocks inside the settings modal |
| 2xl | 48px | Not used by new elements (kept for the scale) |
| 3xl | 64px | Not used by new elements (kept for the scale) |

Exceptions:
- Touch targets are 44px minimum on every control a raider taps (Button `default` is `h-11`, which is 44px). Button `sm` (`h-9`, 36px) is allowed only in officer-only desktop surfaces (expansion toggle row, Discord row), never in the picker or the sheet.
- Every declared spacing value is in the standard set 4, 8, 16, 24, 32, 48, 64. The icon to text gap inside a row is `gap-2` (8px). ScoreSplit tiles use `p-2` and the Total column uses `pl-2` (8px, not 16px) because at 343px content width each of the three columns is about 100px, and a 16px inset would leave about 68px, which is too narrow for a five character Display number (24px, about 72px); with 8px the content box is about 84px and the number fits.
- Rank chip is 32px, slot icon is 24px, meter segment height is 8px (`h-2`).
- No `4.5`, `5.5`, `13` or `15` spacing steps in any new element.

Layout widths: the picker column is one column, `max-w-xl` (576px) and centred from `md` up; on a phone it is full width with 16px side padding. Verified widths: 320px (no horizontal scroll), 375px (the design target), 768px and 1280px.

## Typography

Four sizes, two weights, for every new element in this phase.

| Role | Size | Weight | Line Height | Tailwind |
|------|------|--------|-------------|----------|
| Body | 14px | 400 | 1.5 | `text-md` |
| Label | 12px | 400 (helper text) or 600 (group labels, tile labels, cost marker, badge) | 1.5 | `text-12` |
| Heading | 16px | 600 | 1.25 (nearest standard step, `leading-tight`) | `text-lg font-semibold leading-tight` |
| Display | 24px | 600 | 1.2 | `text-3xl font-semibold` |

Why 14 and 16 both exist: 14px is the phone body size and 16px is the only label size the 44px tap targets use (Button `default` text, row need sentence, sheet question title). The repo's `tailwind.config.js` has an 18px step (`text-xl`) but it is not used, so the two sizes stay at 14 and 16.

Rules:
- Heading (16px) carries the need sentence on a picker row, a preset name, a sheet question title and card titles. Display (24px) carries the picker page title and the score numbers (Standing, Interest, Total).
- Every score number and every budget number gets `.tabular-nums`.
- No text below 12px in any new element. Existing 11px text in the master sheet tooltip stays as it is; new tooltip content is 12px.
- Weight 500 appears only inside the existing Button primitive (`font-medium`) and is inherited, not set by new code.
- Uppercase tracking is used only for the three sheet group labels and the score tile labels, matching the existing `text-12 uppercase tracking-wide` table-header idiom.

## Color

Values come from `DESIGN.md` and match the HSL values in `app/globals.css` converted to hex (verified for `--background`, `--background-subtle` and `--background-elevated` in both modes). The hex comments beside `--background-subtle` in `app/globals.css` (#f2efe9 light, #0d0e11 dark) and beside dark `--background` (#09090c) are stale; the HSL values are the source of truth.

| Role | Value (light / dark) | Usage |
|------|----------------------|-------|
| Dominant (60%) | `--background` #faf8f5 / #060709 | Page behind the picker, Overview, settings |
| Secondary (30%) | `--card` and `--background-elevated` #ffffff / #1d1f25 for rows, tiles, preset cards, score tiles; `--background-subtle` #f3f0ed / #0b0c0f for the sheet surface, the sticky footer and the Fine-tune button | Cards, sheet, footer |
| Accent (10%) | `--accent` #e67300 / #ff8000 (fills, borders at low alpha); `--accent-text` is not used for new text | See reserved list |
| Destructive | `--destructive` #c52020 / #ef4343 | Negative standing figure (with a minus sign), error Alert, rejected badge. No destructive button exists in this phase |

Accent reserved for (and nothing else):
1. The selected state of a preset card (`border-accent bg-accent/5`, the existing radio-card pattern) and of a selected option tile in the question sheet (`border-accent bg-accent/10`).
2. The icon chip and the focus of the Overview "Set your 5" card (`bg-accent/10` chip with an accent icon; its button stays `primary`).
3. The sheet's step progress dots (current dot only).
4. The shared focus ring (`--ring`), through the existing Button, Switch and RadioGroup utilities.

Everything else is neutral: rank chips are `bg-muted`, cost markers are outline badges in `text-foreground-secondary`, the primary buttons are `Button variant="primary"` (inverts black on light, white on dark), the Customised and Custom badges are `Badge variant="outline"`.

Status colors render as fills paired with text, never as colored text on a light surface:
- Pending: `StatusBadge status="pending"`; Approved: `approved`; Needs revision: `needs_revision`; Rejected: `rejected`; Draft: `draft`.
- The over-budget and copy-cap messages sit in a nested panel `bg-warning/10 border border-warning/30` with `text-foreground`. They are guidance, not errors, so they never use `--destructive`.
- Cost is never traffic-light colored. Big, Medium and Standard are told apart by their word and a three-dot decoration (filled dots 3, 2, 1), both neutral. Do not reuse `ClassificationBadge` (Reserved, Limited, Unlimited, red, yellow, green) for needs.

## Surface Specs

### 1. Five-row need picker (DISC-02, 03, 04, 05; D-01 to D-12, D-16, D-27)

When: `/loot-list` renders it instead of the 50-rank editor when every guild-active tier in the selected phase group is Discovery (D-12). Known groups render the editor byte for byte. A mixed group fails closed to the editor (no visual change). The existing phase-group tab control above stays unchanged. The same page is the target of the Overview card and the Discord link (`?guild=<id>&picker=1`); the parameter changes nothing visually.

Page structure, top to bottom, one column:
1. Title block: Display title, order helper (Body, `text-foreground-secondary`), then the character line: character name in the class color through the existing class color helper, followed by the class and spec chip. The chip is a `Badge variant="outline"` rendered as a button (min height 44px tap area), a class color dot, "{Spec} {Class}". It opens the existing EditCharacterModal (UI-07). With no spec set, the chip shows only the class and the picker opens with the no-default state.
2. Status block (only after a first submit): `StatusBadge` plus its sentence, per the state table. It is a `role="status"` region; after a successful save focus moves to it.
3. Helper line: the default-list helper while the list equals the default, the no-default helper for a spec without a default, nothing otherwise.
4. The five rows, an `<ol>` with 8px gaps, each a `Card`:
   - Top line: rank chip (32px circle, `bg-muted`, 14px 600, aria-hidden), slot icon (24px, `text-foreground-secondary`, aria-hidden, from the picker's slot icon map, UI-06), the need sentence (Heading, up to two lines, wraps, never truncates), a trailing `Edit02Icon` (16px, `text-muted-foreground`). The whole top line is one `button` that opens the question sheet at Q1, min height 56px, with a pressed state `bg-muted`.
   - Bottom line: cost marker on the left (outline Badge, 12px 600, word plus three-dot decoration), "Move up" on the right as `Button variant="ghost" size="default"` with `ArrowUp01Icon`. Row 1 has no Move up button.
   - Inline row warning (only when needed): a nested panel line with the over-budget, eligibility or duplicate sentence.
   - Empty row (no default, not yet picked): dashed `border-border-strong`, `PlusSignIcon`, "Pick a need", still opens the sheet.
5. Scope line (Label, `text-muted-foreground`).
6. Sticky footer (`sticky bottom-0`, `bg-background-subtle border-t border-border p-4`, bottom padding adds `env(safe-area-inset-bottom)`): budget sentence (Body, `aria-live="polite" aria-atomic`), a 10-segment meter under it (segments `h-2`, 4px gaps, filled `bg-foreground`, empty `bg-muted`, aria-hidden), then the primary button `size="lg"` full width. When the list is over budget (defensive; the sheet already prevents it) the over-budget sentence replaces the budget sentence and the button is disabled. When fewer than five rows are picked, the button is disabled and the incomplete helper sits under it.

Primary focal point: the sticky footer, that is the budget sentence together with the primary button (the only filled `primary` control on the page). Nothing else on the page uses a filled button or an accent fill at rest, so the eye lands on the footer first and the rows second.

Primary button logic (D-11), one footer button per status. Both save paths run `save_submission_items` then `POST /api/loot-submissions/submit` (D-27); nothing is auto-approved.

| Status of the saved list | Rows | Footer button | Confirm |
|--------------------------|------|---------------|---------|
| Draft or no saved list, list equals the spec default and nothing changed | Editable | "Looks right" (primary) | None |
| Draft or no saved list, any edit, or an empty-start list | Editable | "Save my 5" (primary) | None |
| Pending | Editable; the status block shows Pending | "Save my 5" (primary) | None |
| Rejected or Needs revision | Editable; the status block shows the officer note | "Save my 5" (primary) | None |
| Approved | Read-only: each row is a plain non-interactive Card (no tap target, no Move up) | "Change my 5" (`variant="outline"`, `size="lg"`, full width) | The "Change your 5?" confirm modal; on confirm it calls the audited reopen route (`POST /api/loot-submissions/reopen`), then the rows become editable and the footer button becomes "Save my 5" |

Reordering: "Move up" swaps the row with the one above. Focus stays on the moved row's Move up button (or on the row's main button when it lands at number 1) and a polite live region says "Moved to number {n}." There is no drag and drop on any breakpoint (UI-02). Move up is the only reorder control, so reordering works by keyboard and touch alike.

Tap budget (the 60 second criterion): accepting the default is 1 tap plus a glance. Changing one row is 2 to 3 taps (slot, armour if asked, stat if asked). Five custom rows are at most 15 taps plus Save.

### 1b. Question flow and sheet (D-16; reused by the Phase 5 Drop Desk)

Two components (UI-01):
- `NeedQuestionFlow` is presentational and controlled. It renders only the questions, no dialog. Props: `value` (`{ slot, armour, stat }`, each nullable), `onChange(value)`, `onComplete(need)` (called when the last applicable question is answered), `eligibility` (the eligible set for a class and spec, or null for "any", which the Drop Desk passes when classifying a drop), `optionState(option)` (returns a disabled reason string or null, used for budget, copy cap and duplicates), `variant` (`'sheet'` or `'inline'`). The picker supplies the budget and cap rules through `optionState`; the Desk supplies its own.
- `NeedQuestionSheet` wraps the flow in `Modal` with the new `placement="sheet"` option.

Sheet container: below 640px the dialog is anchored to the bottom edge, full width, `rounded-t-xl`, `bg-background-subtle`, `max-h-[85vh]`, safe-area bottom padding, slides up with `duration-normal` and `ease-out`. From 640px up it is the existing centred `Modal size="sm"`. The standard Modal behaviour (focus trap, inert page, Escape closes the topmost, focus returns to the row that opened it, body scroll lock) is inherited. Backdrop tap closes. There is no drag handle because nothing drags.

Header: `ModalTitle` is the current question (Heading size via `ModalTitle` override to 16px 600), "Question {n} of {m}" beside the step dots (current dot accent, others `bg-muted`), a Back button (`ArrowLeft01Icon`, 44px) from the second question on, and the standard close button. Under the header, the building sentence ("Picking: Chest, Plate") in Label style, `aria-live="polite"`.

Questions (at most three, any question already decided is skipped):

| # | Shown when | Options | Layout |
|---|------------|---------|--------|
| Q1 slot | Always | Slot tiles in three groups. Weapons: Two-hand weapon, Main hand weapon, Off-hand weapon, Ranged weapon, Shield, Off-hand item, Relic. Armour: Head, Shoulders, Chest, Wrist, Hands, Waist, Legs, Feet. Accessories: Neck, Ring, Back, Trinket. Slots the class cannot use are hidden (D-10); a group with no slots is hidden with its label | 3 columns at 375px, 8px gaps, tile min height 80px: icon 24px, label 12px 600 (wraps to two lines), cost word 12px 400 muted. Current slot carries a "Current" tag; selected tile is accent. 4 columns from 640px |
| Q2 armour | The chosen slot is one of the eight armour slots AND the class can wear more than one armour class that has at least one usable stat for the spec | Cloth, Leather, Mail, Plate, only the ones the class can wear with a usable stat. Default highlighted is the class's top armour, tagged "Your armour" | Full width rows, min height 56px, radio semantics |
| Q3 stats | More than one stat family is usable for the chosen slot (and armour) for this spec | Strength, Agility, Tank, Spell damage, Healing, Physical, filtered by the taxonomy and the spec. Default highlighted is the spec's own family | Full width rows, min height 56px; "Physical" has the helper "Strength or agility" |

Not in the flow (UI-03): a weapon type question and a "lighter armour is fine too" checkbox. The frozen taxonomy has no weapon type and no lighter-armour key, so neither can be saved as a need. Lighter armour matching is decided later by the Drop Desk match rule.

Behaviour:
- Auto-advance: tapping an option answers the question and moves to the next after 150ms (`duration-fast`). With `prefers-reduced-motion` there is no delay and no slide. On advance, focus moves to the new question title (`tabIndex=-1`) so a screen reader reads it first.
- Options are buttons with `aria-pressed` for the current answer. Disabled options use `aria-disabled` plus `aria-describedby` pointing at the reason text, and remain focusable.
- Last applicable answer commits: `onComplete` fires, the sheet closes, focus returns to the row, and the row background pulses `bg-muted` for `duration-slow` (a neutral highlight, not accent). If a duplicate or cap would be created, the last question's option is disabled with the label "In your 5" and cannot commit.
- Over budget is blocked at Q1, because cost depends only on the slot (UI-04). The budget used for the check excludes the row being changed, so swapping a Big for another Big is allowed. A slot that would push the total over 10 stays on screen but is `aria-disabled`; tapping it shows the over-budget sentence in a nested warning panel at the top of the sheet (`role="alert"`) and does not advance. The panel clears when another slot is tapped.
- Ring and Trinket: a second copy is allowed (and costs again); a third shows "You already have two of these in your 5." Any other need twice shows "That need is already in your 5.", at Q1 when the slot has no armour or stat questions left to ask, otherwise at the last question.
- Back keeps the earlier answers selected. Closing the sheet discards an unfinished change; the row keeps its old need.

### 2. "Set your 5" Overview card and the Discord message (D-14, D-23, D-24)

Overview card: shown to a raider in a Discovery guild whose character has no submitted Discovery list (Pending, Approved, Needs revision and Rejected count as submitted; none, or only a Draft, shows the card). It is a full-width `Card` at the top of the Overview content, above the Insights row, `p-4 sm:p-6`. Phone: icon chip (40px, `bg-accent/10`, accent `Target02Icon` at 20px) above the text, then heading (Heading), body (Body, `text-foreground-secondary`), then a full-width `Button variant="primary" size="default"` "Set my 5" (link to `/loot-list?picker=1`). ## Interaction, Accessibility and Responsive Rules

- Touch: every tappable control in the picker and the sheet is at least 44px tall and wide; rows and tiles are the full hit area. Verify at 320px and 375px: no horizontal scroll, no clipped need sentence, sticky footer never covers the last row (add bottom padding equal to the footer height to the list).
- Keyboard: the rows are `<ol>`; the row's main button has the accessible name "Number {n}: {sentence}. {Big, Medium or Standard} pick. Change." Move up has the name "Move {sentence} up to number {n minus 1}". Sheet options are buttons with `aria-pressed`. Escape closes the topmost sheet or modal (inherited).
- Live regions: budget sentence (`polite`, atomic), move announcement, building sentence, save status, send result. Errors that block (`role="alert"`): the over-budget or cap panel in the sheet, the 409 reason, save and load errors.
- Contrast: use only text tokens in the DESIGN.md contrast record (`--foreground`, `--foreground-secondary`, `--foreground-muted` on `--card` or `--background-elevated`). No `--accent-text` for new text, no status colors as text on light surfaces.
- Motion: sheet slide and step advance use `duration-normal` and `duration-fast`; every transition carries `motion-reduce:transition-none` and auto-advance drops its 150ms delay under `prefers-reduced-motion`. `animate-pulse` is used only by the skeleton.
- Meaning never rests on color or icon alone: cost has its word, status has its badge text, Customised has its word, the minus sign marks a negative Standing.
- Desktop: hover `bg-muted` on rows and tiles, no drag, same single column, the sheet becomes a centred `Modal size="sm"` from 640px.
- Zoom and long text: no fixed heights on text containers; the sheet scrolls inside `ModalBody`; the need sentence wraps to two lines at 375px and to three at 200% zoom without clipping.

Facts found during planning (all checked against origin/main aafb4a63):

1. Seeder (app/services/expansionSeeder.ts). Classification comes from ITEM_CLASSIFICATIONS[item.name] and defaults to 'Unlimited', so the cost is 0. Roles come from CLASSIC_ITEM_ROLES[item.name] and default to []. loot_item_classes rows are written only for isTokenSlot slots, and TOKEN_SLOTS is ['Token']. None of the 21 recipe names is in data/classic-wow-item-classifications.ts or data/classic-item-roles.ts. So the seeder writes each recipe as Unlimited, cost 0, roles [], with no class rows. No seeder change is needed.

2. Picker (lib/loot-items-query.ts fetchFilteredLootItems). For a non-token row, it takes armor and weapon type from the DB row (the seeder leaves them null). Next it tries getItemTypeInfo(wowhead_id) from data/item-types.ts, then inferArmorType and inferWeaponType. Both infer functions return undefined for slot 'Recipe', because 'Recipe' is not an armor or weapon slot. Then isClassAgnosticSlot('Recipe') returns true ('Recipe' is in CLASS_AGNOSTIC_SLOTS in data/class-proficiencies.ts). Result: every class sees every recipe. Note the ordering: the weapon check runs BEFORE the class-agnostic check. An ITEM_TYPES weapon_type entry on a recipe (for example Gun for Schematic: Core Marksman Rifle) would therefore hide it from classes without that proficiency.

3. data/item-types.ts holds only armor_type and weapon_type. The TBC recipes (#200/#209, the D-03 template) have no entries there. The existing completeness check "every ITEM_TYPES entry for a Classic catalog item agrees with the package" compares JSON.stringify(entry) with JSON.stringify(packageTypeInfo(item)). For a package item of class 'Recipe', packageTypeInfo returns null, so any entry for a recipe, even an empty one, fails that check. Decision (planner, flagged to the orchestrator as OD-01): the task wording lists data/item-types.ts among PR 1's files, but PR 1 adds no ITEM_TYPES entries for recipes. It adds a short doc comment in item-types.ts recording why, and the new gate asserts that no recipe has an entry.

4. Icons. data/item-icons.ts is a Record keyed by wowhead_id. None of the 21 ids is present today. The GH-273 icons were appended as a commented "Manually added for GH-273" block at the end of ITEM_ICONS; GH-284 follows the same pattern. The package icons are 'inv_scroll_05' for all Pattern, Plans, Schematic and Recipe items, and 'inv_misc_note_01' for all Formula items. The completeness suite already requires an icon for every catalog entry. One entry per id: the 7 shared AQ ids get one icon each, not two. tsc rejects duplicate keys in an object literal, so a duplicate is caught.

   - The #273 migration guards are both scoped by li.raid_tier_id = rt.id, so an AQ40 row cannot block the AQ20 insert.

For a shared formula, it picks the lowest raid_tier_id among the guild's AQ20 and AQ40 rows, so an AQ40 drop recorded through the addon can be filed under the AQ20 tier.

# Quick Task 261003-m45: Officer writes check the character belongs to the guild Summary

**Two SECURITY DEFINER triggers (enforce_guild_character_refs, enforce_attendance_character_refs) stop any writer, including service-role app routes, from attaching another guild's character (or, for raid_team_members and donation_records, a raider who has left) to a guild's team roster, donation ledger or raid attendance.**

## OD-0 and OD-1 Resolutions (as applied)

- **OD-0 (scope split):** this task covers only `raid_team_members`, `donation_records` and `attendance_records`. `blp_credits`, `blp_tracking` and `reserve_awards` are deferred to a second quick task (FU-1 below) because they are written only by SECURITY DEFINER recompute functions / need a different rule shape, not by user-facing writes that already self-check membership.
- **OD-1 (attendance membership rule):** option A, an attendance row accepts **any** membership row of the character in the raid event's guild, active or not. This keeps the raid-tracking import's one-upsert-per-night write shape from failing silently if a raider's membership changed after the roster was loaded. A character who was never a member of that guild is still refused either way.
- **COPY sign-off:** C-1 (`raid_team_members.character_id is not an active member of this guild`), C-2 (`donation_records.character_id is not an active member of this guild`) and C-3 in its OD-1 A form (`attendance_records.character_id is not a member of this guild`) were approved by the user on 2026-10-03 and shipped verbatim. ## Context Findings (verified at WT 1a0e6473, 41/41 migrations applied in PGlite)

1. **Rules today:** `raid_team_members` and `donation_records` INSERT/UPDATE/DELETE policies check only `is_guild_officer(guild_id)`; `attendance_records` policies check only that the caller is an officer of the raid event's guild. No existing trigger or rule looked at which character a row names.
2. **Probe facts:** an officer session of guild A could insert a `raid_team_members`, `donation_records` and `attendance_records` row for a character of guild B, or for a character whose guild A membership was inactive, and all of those writes succeeded before this migration. The candidate trigger bodies (run in-memory against the same fixtures) correctly refused those writes with a DETAIL, masked the refusal to RLS's own error for non-officers, and left every legitimate write shape (legacy edits, same-guild moves, bulk upserts, auto-link, character delete) working.
3. **Membership evidence per table:** raid team rosters are current (`POST /api/raid-teams/[id]/members` refuses a non-active character before writing); donations are logged for current members (`POST /api/donations` has the same pre-check); attendance records a past raid night, so it uses the looser OD-1 A rule instead.
4. **Writer inventory:** every writer of the three tables (the raid-teams members route, the donations routes, `/api/attendance/bulk`, `/api/attendance/auto-link`, `importAttendanceByTeam`, the raid-tracking import client, `scripts/backfill-team-event-routing.ts`, and the referential-action deletes) sends only characters it has already checked, or changes no reference column, or moves an attendance row within one guild. All of these shapes are covered by a PGlite check in this task.
5. **Re-write paths:** no migration, backfill, or bulk path re-writes a reference column of an existing row in a way this rule refuses; donation and attendance PATCH routes never touch the reference columns the triggers watch.
6. **Tests:** every other migration shape test checks only its own timestamp (none scans the live migrations directory), and the function-grants ratchet test (`function-execute-grants-migration.test.ts`) requires every new function's REVOKE to include PUBLIC, which both new functions satisfy.

```sql
select 'raid_team_members' as table_name, count(*) as rows_with_character,
       count(*) filter (where not exists (select 1 from public.character_guild_memberships m
                         where m.character_id = t.character_id and m.guild_id = t.guild_id and m.is_active)) as no_active_membership,
       count(*) filter (where not exists (select 1 from public.character_guild_memberships m
                         where m.character_id = t.character_id and m.guild_id = t.guild_id)) as no_membership_row
  from public.raid_team_members t
union all
select 'donation_records', count(*),
       count(*) filter (where not exists (select 1 from public.character_guild_memberships m
                         where m.character_id = t.character_id and m.guild_id = t.guild_id and m.is_active)),
       count(*) filter (where not exists (select 1 from public.character_guild_memberships m
                         where m.character_id = t.character_id and m.guild_id = t.guild_id))
  from public.donation_records t
 where t.character_id is not null
union all
select 'attendance_records', count(*),
       count(*) filter (where not exists (select 1 from public.character_guild_memberships m
                         where m.character_id = t.character_id and m.guild_id = re.guild_id and m.is_active)),
       count(*) filter (where not exists (select 1 from public.character_guild_memberships m
                         where m.character_id = t.character_id and m.guild_id = re.guild_id))
  from public.attendance_records t
  join public.raid_events re on re.id = t.raid_event_id
 where t.character_id is not null;
```

Run queries 2 and 3 **after the deploy** (about 12 seconds after merge) to confirm the three triggers exist and only `service_role` has EXECUTE:

```sql
select c.relname as table_name, t.tgname as trigger_name
  from pg_trigger t
  join pg_class c on c.oid = t.tgrelid
  join pg_namespace n on n.oid = c.relnamespace
 where n.nspname = 'public' and not t.tgisinternal
   and t.tgname in ('enforce_guild_character_refs', 'enforce_attendance_character_refs')
 order by 1;

select p.oid::regprocedure::text as function,
       has_function_privilege('anon', p.oid, 'EXECUTE') as anon,
       has_function_privilege('authenticated', p.oid, 'EXECUTE') as authenticated,
       has_function_privilege('service_role', p.oid, 'EXECUTE') as service_role
  from pg_proc p
  join pg_namespace n on n.oid = p.pronamespace
 where n.nspname = 'public'
   and p.proname in ('enforce_guild_character_refs', 'enforce_attendance_character_refs')
 order by 1;
```

The migration does not check or change any existing row; query 1's counts are informational only, to size how many legacy rows would be refused if their character or guild were later changed.

### Auto-fixed Issues

**1. [Rule 1 - Bug] `tsc --noEmit` failed on the shape test's `ATT_RULE` comparisons**
- **Found during:** Task 3, step 2 (tsc gate)
- **Issue:** `const ATT_RULE: 'any' | 'active' = 'any'` let TypeScript's control-flow analysis narrow the variable to the literal type `"any"` for the rest of the file (since it is never reassigned), so the `ATT_RULE === 'active'` comparisons used by the OD-1-B branch of the attendance body test were flagged as `TS2367: This comparison appears to be unintentional because the types '"any"' and '"active"' have no overlap`.
- **Fix:** Typed the constant as plain `string` instead of the narrower union, so both comparison branches stay meaningful to tsc regardless of which OD-1 option is live.
- **Files modified:** `app/services/__tests__/team-donation-attendance-character-rules-migration.test.ts`

## Production catalog check (read-only; schema metadata and aggregate counts only; the user runs it in the Supabase SQL editor, never the executor)

```sql
-- 1. Before merging and after the deploy: policies on the two tables and whether each checks is_active
--    Before: loot_submissions has 9 rows (the two this task drops show false); expansions has 5 (the three officer policies false).
--    After: loot_submissions has 7 rows; with OD-1 A the three expansions officer policies show true.
select tablename, policyname, cmd,
       (coalesce(qual, '') || ' ' || coalesce(with_check, '')) like '%is_active%' as checks_active
  from pg_policies
 where schemaname = 'public' and tablename in ('loot_submissions', 'expansions')
 order by 1, 2;

-- 2. Before merging: the current expressions of the policies this migration changes,
--    to compare with the header Rollback (which recreates them from the baseline text)
select tablename, policyname, cmd, qual, with_check
  from pg_policies
 where schemaname = 'public'
   and policyname in ('Guild members can view guild submissions', 'Officers can manage submissions',
                      'Officers can insert expansions', 'Officers can update expansions', 'Officers can delete expansions')
 order by 1, 2;

-- 3. Optional, before merging: how many (user, guild) pairs have a membership row but no active one (count only)
select count(*) as inactive_only_user_guild_pairs
  from (select c.user_id, cgm.guild_id
          from public.character_guild_memberships cgm
          join public.characters c on c.id = cgm.character_id
         where c.user_id is not null
         group by c.user_id, cgm.guild_id
        having not bool_or(cgm.is_active)) s;
```

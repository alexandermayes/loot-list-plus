**One migration-only PR drops the `loot_submissions` policies that let an inactive guild membership keep reading or officer-updating a guild's loot lists, and (OD-1 option A) adds the same active-membership condition to the three expansions officer write policies, proven in PGlite against both the forward migration and its header Rollback.**

## Reader and writer table (investigation finding 4, re-verified)

Every user-session reader of `loot_submissions` filters to `activeGuild.id` (the user bundle lists active memberships only) or to the caller's own character: `LootSubmissionsContent.tsx`, `master-loot/_client.tsx`, `MasterSheetContent.tsx`, `lib/loot/master-sheet-summary.ts`, `DashboardContent.tsx` and its `loot_submissions!inner` embeds, `SetupGuide.tsx`, and `LootListContext.tsx`'s upserts. Every other reader (review, revert, submit, delete, remove-item, item-counts, statuses, resubmit routes, bot, cron, admin, audit-logs) uses the service role and bypasses RLS. Nothing writes expansions through a user session outside the three recreated policies: every app write goes through a service-role route or the SECURITY DEFINER `create_expansion_for_guild`. No Realtime channel or view reads these tables, so the drop and the added conjunct cannot surface stale rows anywhere else. `lib/database.types.ts` has no policy names, so it is unaffected.

## Production catalog queries (read-only; the user runs these, never the executor)

Run query 1 before merging (expect `loot_submissions` 9 rows, the two dropped policies showing `checks_active = false`; `expansions` 5 rows, the three officer policies showing `false`) and query 2 before merging (to compare the live expressions against the header Rollback). Run query 1 again after the deploy (expect `loot_submissions` 7 rows; the three expansions officer policies now showing `checks_active = true`). Query 3 (optional) counts `(user, guild)` pairs with a membership row but no active one, for context only.

```sql
-- 1. Before merging and after the deploy
select tablename, policyname, cmd,
       (coalesce(qual, '') || ' ' || coalesce(with_check, '')) like '%is_active%' as checks_active
  from pg_policies
 where schemaname = 'public' and tablename in ('loot_submissions', 'expansions')
 order by 1, 2;

-- 2. Before merging: current expressions of the policies this migration changes
select tablename, policyname, cmd, qual, with_check
  from pg_policies
 where schemaname = 'public'
   and policyname in ('Guild members can view guild submissions', 'Officers can manage submissions',
                      'Officers can insert expansions', 'Officers can update expansions', 'Officers can delete expansions')
 order by 1, 2;

-- 3. Optional, before merging: (user, guild) pairs with a membership row but no active one
select count(*) as inactive_only_user_guild_pairs
  from (select c.user_id, cgm.guild_id
          from public.character_guild_memberships cgm
          join public.characters c on c.id = cgm.character_id
         where c.user_id is not null
         group by c.user_id, cgm.guild_id
        having not bool_or(cgm.is_active)) s;
```

<objective>
Stop the daily resubmit-reminder DMs, the sidebar badge and the dashboard alert from counting lists of raiders who left the guild. When a raider leaves or is kicked, the database auto-rejects their pending and approved lists in that guild. The reminder cron treats every rejected list (and every edited-after-submit draft) as needing a resubmit with no membership check, so a raider who left can get up to three Discord DMs asking them to resubmit lists the app will refuse to submit ("Your character needs to rejoin this guild."). The badge route counts every character the user owns, so an alt that left still raises the badge in a guild where the main is active.

Purpose: reminders and badges should only ask for something the raider can actually do. The submit route already decides that with findInvalidCharacterIds(service client, list guild_id, [list character_id]); this plan applies the same check, per list, to the cron and the badge.

Output: one small lib helper (keepListsOfActiveMembers) with tests, the cron wired through it with route tests, the badge route filtered with route tests, a docblock note on the status rule, two or more commits in WT, a PR body draft in SP and a SUMMARY in MAIN. No push, no PR, no migration, no SQL.

This is exactly the submit route's check (fact 5), and the auto-reject trigger also works per character and guild (fact 3). Never suppress per user account: a user can have a main still active in the same guild, or the same character active in another guild, and those lists are still actionable.

Lists with a null or empty guild_id or character_id are dropped (they cannot be submitted either). Empty input makes no query. Errors propagate.

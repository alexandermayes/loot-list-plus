- D-02 (manage rule and helper): new module lib/discord-server-access.ts (no next/server import). It exports: canManageDiscordServer(guild) returning true when guild.owner is true or the BigInt of guild.permissions has bit 0x8 (Administrator) or 0x20 (Manage Server); a permissions string that BigInt cannot parse counts as false. Use BigInt(0x8) and BigInt(0x20), not bigint literals (tsconfig targets ES2017). checkUserManagesDiscordServer(serverId) returns { ok: true } or { ok: false, reason } with reason one of 'not_manager', 'token_expired', 'rate_limited', 'discord_error'. It creates the user's server client with createClient from @/utils/supabase/server, takes session.provider_token from auth.getSession(), tries auth.refreshSession() once when it is missing (the same steps as getDiscordToken in app/api/discord-guilds/route.ts), returns token_expired when there is still none, then calls GET https://discord.com/api/v10/users/@me/guilds with the Bearer token using plain fetch (no retry wrapper, as the other user-token routes do).

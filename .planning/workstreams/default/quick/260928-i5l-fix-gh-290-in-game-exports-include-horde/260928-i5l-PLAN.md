<objective>
Fix GH #290. When a Horde guild loots its own quest head (Head of Nefarian 19002, Head of Onyxia 18422), in-game tools should still find the LootList+ data that the catalog stores under the Alliance ids (19003, 18423). Each exporter's format was checked, and the fix is chosen per exporter (see exporter_decisions):
- LootList+ addon exports (guild-data for the companion, export-string for the addon): mirror each faction-variant entry under the other faction's id, with identical data (PD-01, PD-02). No companion or addon change is needed (PD-05).
- Gargul DFT prio and Gargul soft-reserve exports: do NOT mirror. Gargul already links both head pairs natively, and a mirror would double-list raiders and double-count reserves. The decision is documented in code and locked by tests (PD-03, PD-04).
- A pre-existing bug on the companion path is fixed in its own commit: guild-data selects a column that does not exist, so it always returns no items (OD-01).

Purpose: Horde officers get the same in-game prio data as Alliance officers, and no exporter double-counts.
Output: one branch, fix/290-export-faction-aliases, with a DRAFT PR against main that says "Fixes #290".
</objective>

## OD-01 (INCLUDED as its own commit, droppable): guild-data selects a nonexistent loot_items column
GET /api/addon/guild-data selects 'id, name, wowhead_id, boss_name, slot, item_type, classification, raid_tier_id' from loot_items. loot_items has item_slot and no slot column: see the baseline migration, lib/database.types.ts, and the fact that no later migration adds one. export-string correctly selects item_slot. PostgREST rejects the unknown column, and the route ignores the error, so items is always [] and priorities is queried for zero ids. Without this fix, PD-01's items half is a no-op on the companion path. The fix changes that select to item_slot and maps slot from item.item_slot (the output key stays slot, which the companion's GuildData type reads). It is committed separately, so the user can drop that one commit if they want it in a separate issue. The PR body lists it under "Also fixed".

Both routes authenticate with getAuthenticatedUser, which reads only the session cookie, so the companion path probably returns 401 today. The live in-game exports are the two Gargul exports, and they already work for Horde guilds through Gargul's own item links. Reported in the PR body so the user can confirm the #290 symptom was seen in Gargul or was anticipated.

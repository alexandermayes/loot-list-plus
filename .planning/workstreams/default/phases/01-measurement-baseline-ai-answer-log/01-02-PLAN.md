<objective>
Build the MEAS-02 instrument: a self-contained weekly procedure document plus an append-only results log with a validating appender, so any future run is repeatable and no recorded cell can be silently corrupted or paraphrased.

Purpose: nothing in the repo currently defines the AI-answer test at all. The prompts and cluster lists live only in a sprint plan document outside the repository, and the phase goal explicitly requires a future run to be possible without re-reading it. The log accumulates weekly for four weeks and is read by the Phase 6 review, so its schema and its quoting have to be right on the first write.
Output: `RUNBOOK.md`, an empty-of-data `ai-answer-log.csv`, a stdlib appender, and a test module that pins the schema and keeps the runbook and the code from drifting apart.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| human browser session to reported results | Answers observed in a browser are retyped or pasted into a CLI; nothing verifies them mechanically |
| appender CLI to committed CSV | Operator supplied free text (cited_url, competing_sources, notes) crosses into a file that is committed to a confirmed PUBLIC repository |
| committed log to Phase 6 review | The log is the only evidence Phase 6 has about AI answers |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-07 | Tampering | `append_row` writing operator free text into the CSV | medium | mitigate | All writing goes through `csv.writer`, never a comma join, so a value containing commas or quotes cannot shift columns. Pinned by the round-trip test in Task 1. |
| T-01-08 | Repudiation | `read_rows` and the append-only contract | medium | mitigate | `read_rows` never sorts, dedupes, or rewrites, and `append_row` only appends, so a re-run of a cell adds a visible second row instead of silently replacing the first. Pinned by the duplicate-triple test. |
| T-01-09 | Information Disclosure | free-text `notes` and `cited_url` committed to a public repository | low | mitigate | The runbook restricts these fields to the observed answer content and the sites it named. It instructs the operator never to paste account identifiers, session URLs, or personal browsing detail. No account or identity field exists in the schema. |
| T-01-10 | Spoofing | a logged-in or personalised session presented as a clean one | medium | mitigate | Per-surface session-hygiene steps are mandatory and numbered in the runbook, and the runbook states that a personalised session biases every future comparison. Enforcement is procedural, which is why the first run is a human checkpoint in plan 01-04 (D-02) rather than an automated step. |
| T-01-SC | Tampering | npm / pip / cargo installs | high | accept | No package-manager install occurs. Stdlib-only Python per repo convention; RESEARCH.md's Package Legitimacy Audit records the gate as not applicable, so there is no `[ASSUMED]` or `[SUS]` package to verify. |

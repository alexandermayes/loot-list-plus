# Phase 4 — UI Design Contract

> Visual and interaction contract for the case-study template rendering at `/customers/{guild-slug}`.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope note (mirrors 04-RESEARCH.md exactly):** This phase splits into an unblocked
> template (EVID-04) and content that cannot exist yet (EVID-05, blocked on a user-conducted
> guild interview). This contract governs the **template's design contract** — every visual
> rule an executor needs to render the page correctly once real, interview-approved content
> exists. It contains **zero invented guild names, quotes, or outcome numbers**; every content
> row below uses the sprint plan's literal `{token}` placeholders, exactly as RESEARCH.md's
> Code Examples section quotes them. No case study is designed to ship reachable/indexable
> with fixture content — see Copywriting Contract "Empty state" and UI Considerations.
> This contract deliberately reuses Phase 3's locked tokens (spacing, typography, color) rather
> than re-deriving them, per RESEARCH.md's own instruction to treat Phase 2/3 primitives as
> "already built and locked" — the two evidence pages should read as one visual family.

## Typography

Consolidated to exactly **4 sizes**, identical to Phase 3's locked scale — this is a deliberate cross-page consistency decision (see scope note above), not independent re-derivation.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label (eyebrow tag, breadcrumb, byline, proof-strip captions, verification line) | 16px (`text-lg`), distinguished by `text-foreground-muted` color and/or `uppercase tracking-wide`, never by a separate size | 400 regular | 1.5 |
| Body (lead paragraph, before/after narrative panels, quote text, credible-limitation prose) | 16px (`text-lg`) | 400 regular | 1.5 |
| Heading (before/after panel labels "Before LootList+" / "After LootList+", the credible-limitation section label, H2-level subheads if any exist) | 20px (`text-2xl`) | 700 bold | 1.2 |
| Display (H1 — outcome-focused title) | 32px (`text-4xl`) at all breakpoints, single value, no mobile/desktop split — matches Phase 3's consolidation | 700 bold | 1.2 |

Four distinct pixel values ship: **16, 20, 32, 42** — identical set to Phase 3. Declared weights: **2** — 400 (regular, body/label/meta) and 700 (bold, headings, H1, proof-strip numbers, CTA button label, quote-card author name inherits its existing 600/semibold treatment as an accepted carry-over from `QuoteCard`, same exception Phase 3 granted the blog byline).

Exception (inherited component, not a new addition): `QuoteCard`'s author name uses `font-semibold` (600) per its existing implementation in `LandingValueProps.tsx` — reused as-is, not re-styled, so this case study's single quote visually matches the homepage testimonials exactly.

## Color

Reuses the existing dark-mode design tokens (`app/globals.css`, `:root.dark`) — identical values to Phase 3, since `defaultTheme="dark"` is the site default.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `hsl(230 18% 3%)` ≈ `#09090c` (`bg-background`) | Page background |
| Secondary (30%) | `hsl(228 12% 8%)` ≈ `#141519` (`bg-background-elevated`) | Proof-strip stat-block backgrounds, before/after narrative panel backgrounds, credible-limitation box background, contextual-CTA box background |
| Accent (10%) | `hsl(30 100% 50%)` ≈ `#ff8000` (`text-accent` / `bg-accent`) | Reserved for exactly: (1) the four proof-strip stat numbers, (2) the public-profile outbound link (question 10) when one exists — via `QuoteCard`'s existing `text-accent hover:underline` treatment on the guild name, (3) the "Verified LootList+ customer" note stays `text-[#bababa]` (muted, per `VerificationLine`'s existing implementation — **not** accent, do not recolor it), (4) the single CTA button, (5) the eyebrow label (e.g. "Case Study") if used, matching the report's eyebrow-tag convention |
| Destructive | `hsl(0 84% 60%)` ≈ `#ef4444` (`text-destructive` / `bg-destructive`) | **Not used.** The credible-limitation section (interview question 9, "what still needs improvement") must render in the standard body-text treatment, the same decision Phase 3 made for its own "limits" paragraphs. A guild's honest limitation is not a warning or an error — coloring it destructive/red would misrepresent a credibility feature as a problem notice. |

Accent reserved for: the four proof-strip numbers, the outbound public-profile link, the CTA button, and the optional eyebrow label. Never used for the verification-line text, panel borders, or plain narrative body copy.

## Focal Point / Visual Hierarchy

| Priority | Element | Why |
|----------|---------|-----|
| 1 — Primary anchor | The proof strip (four 42px accent stat numbers in a row/2×2 grid, directly under the lead paragraph) | This is the phase's entire reason for existing: checkable, at-a-glance proof (roster size, expansion/tier, before→after metric, months using LootList+). It must out-rank the surrounding prose exactly the way Phase 3's stat callouts out-rank their prose. |
| 2 — Secondary | The before/after narrative panels and the quote block (with its verification line) | Read, not scanned — these substantiate the proof strip's numbers with the guild's own account and voice. The quote reuses the exact homepage `QuoteCard` visual treatment so a returning visitor recognizes it as the same class of evidence as the homepage testimonials. |
| 3 — Tertiary | The lead paragraph, the credible-limitation section, and the contextual CTA | Lead paragraph sets context before the proof strip lands; the limitation section is deliberately understated (standard body treatment, no accent, no destructive color) so it reads as honest rather than alarming; the CTA is a conversion ask placed after all proof has landed, mirroring Phase 3's CTA placement. |

Rule of thumb for the executor: **the proof strip's four numbers must be the single largest, most saturated elements on the page.** The H1 (32px) is allowed to be prominent at the very top, but nothing below it — not the panel headings, not the quote, not the CTA heading — should approach the H1's weight. Hierarchy resets to "proof strip wins" as soon as a reader scrolls past the lead paragraph.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **Draft, not locked — subject to this phase's own copy sign-off gate** (ROADMAP.md: "Copy sign-off is a hard gate... applies to the visible copy in Phases 3 and 4 as well"). Recommended starting point, mirroring Phase 3's exact CTA for visual-family consistency: **Heading:** "See how the same rules work with your roster." **Body:** "Create a free guild, import your raiders, and compare the priority order before your next raid night." **Button label:** "Create your guild free." This CTA is guild-agnostic (no interview-dependent content), so a draft may be proposed here — but it still requires explicit user sign-off before ship, same as every other visible string on this page. |
| Empty state | **Not applicable to a shipped page** — mirrors Phase 3's D-05 build-time-import reasoning. There is no "zero case studies" runtime UI state to design: if the case-study data module has zero entries, `generateStaticParams()` returns `[]` and the route is unreachable by any real URL — there is no page for a visitor to land on and see "empty." An unmatched/invalid slug renders Next.js's standard 404, not a custom empty state. **Do not build a "coming soon" placeholder page at a real, reachable URL** — that would be exactly the fabricated-example anti-pattern RESEARCH.md's Pitfall 1 forbids. |
| Error state | **Not applicable**, same reasoning as Phase 3 — no client-side fetch, no form submission, nothing that fails at request time. The public-profile outbound link (if present) points to a URL the guild itself supplied; a broken external link is a content-accuracy issue caught at copy sign-off, not a UI error state to design. |
| Destructive confirmation | **Not applicable.** No destructive action exists on this page. |

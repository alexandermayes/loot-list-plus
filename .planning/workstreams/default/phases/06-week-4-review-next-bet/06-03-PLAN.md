<objective>
Give the review a combined page and query Search Console export and a committed, data-relative rule for which pages have meaningful impressions at positions 4 to 20 with weak CTR.

**As a** founder choosing the next bet, **I want to** see which pages already earn impressions at positions 4 to 20 but lose the click, under a rule fixed before I look at the list, **so that** the bet improves a page that is already close rather than one I happened to like.

Purpose: success criterion 2 names pages, but position and CTR are per query; a page-level average hides the query that matters. The GSC API supports the combined dimension and pull-gsc.py's query function already accepts any dimensions list, but the CLI and CSV writer only handle one dimension. D-11 requires a data-relative rule stated before candidates are listed; putting the rule in tested code, and printing it first, is what makes that auditable. D-12 reuses the clusters for the baseline-week comparison.

Output: the page-query export path (pull-gsc.py plus gsc_export.py, tested), and gsc_review.py with its tests. No Search Console call is made in this plan; plan 06-06 pulls the data once Sep 24 is final.
</objective>

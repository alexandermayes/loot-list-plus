<objective>
GH #278: PR #275 added data/__tests__/classic-catalog-completeness.test.ts, whose completeness gate only considers wow-classic-items entries that carry a source.zone in one of the seven Classic raid zones. The planner measured the gap on origin/main at d8416c92 with the installed wow-classic-items 2.0.1: 40 of the 736 unique Classic catalog ids have no zone. Eight are Rare recipes already gated by the 'Classic raid profession recipes (#284)' describe (the seven AQ formulas 20727, 20728, 20729, 20730, 20731, 20734 and 20736, listed in both AQ raids, plus 21371 Pattern: Core Felcloth Bag). The other 32 are Epic and are the issue's list: every Onyxia's Lair drop (18 ids, the nine Tier 2 helms among them), the five Cache of the Firelord items under Majordomo Executus that are not in GH273_CORE's wider zone coverage, and the nine Four Horsemen Chest items in Naxxramas (six under Four Horsemen, the three chest Desecrated tokens under Tier 3 Tokens). Removing any of these 32 from the catalog, or never adding one, passes the suite today.

Two findings shape the fix:
1. For all 32 ids the package record has no source field at all, not merely no zone (the eight recipes have {category: 'Rare Drop', dropChance} and nothing else). There is no boss or NPC name in the package to key a mapping on, so the issue's "boss or NPC to raid mapping" has to be a checked-in fixture keyed by the in-game drop source: Cache of the Firelord and the Four Horsemen Chest are game objects, not NPC loot, and the package has zero items under Onyxia's Lair zone 2159, so the whole Onyxia raid has no completeness coverage today.
2. Every package-zoned catalog row sits under the raid its zone names (838 rows, 0 mismatches), so an inverse check "every catalog row is covered by the package zone, the fixture, or the Recipe gate" can be strict with no further exclusions.

The catalog itself is hand-maintained; .github/workflows/refresh-item-data.yml only regenerates data/item-icons.ts and data/item-unique.ts from it, so nothing in the generator needs to change.

Task 1 is the tracer: the fixture module with the source-to-raid map but no rows, the three-path coverage check wired into the completeness suite, a RED run that reports exactly the 32 ids, then the 32 rows and a GREEN run. Task 2 gives the fixture its own test, unions the fixture into the existing missing-items check, adds the placement it.each, and proves the gate bites by temporarily removing Shard of the Scale (17064) from the catalog and from the fixture. Task 3 adds the catalog header sentence, runs the three verification commands, and opens the PR.

Purpose: a future catalog edit that drops an Onyxia helm, a Cache item or a Four Horsemen Chest item fails CI instead of reaching every newly seeded Classic guild as a silent gap, and a package update that starts attributing those items is caught so the fixture shrinks rather than going stale.

# Quick 261016-l9e: align the raid_roles_overall_bonus_priority default (GH #411)

## Objective

`domain/scoring/defaults.ts` said `raid_roles_overall_bonus_priority: false` while the `guild_settings` column default and the GET fallback in `app/api/guild-settings/route.ts` both say `true`. #399 closed the same split for `single_raider_overall_bonus`; #411 was left out because flipping it changes whether role bonuses apply for callers that score with a partial config and no settings row.

## Decision

Align the code default to `true`. Every production scoring path loads a settings row or the GET fallback, so the database value is what guilds run with; the code default only reaches partial-config callers. With the flag flipped, the domain, guild-settings and sheet-import suites pass unchanged (752 tests), so nothing in the repo relied on `false`. Role bonuses still need `role_modifiers` entries, which default to empty, so a guild that never set them sees no change.

2. Pin it in `domain/scoring/__tests__/calculations.test.ts` next to the #399 assertion (`// regression for #411`).
3. Run the scoring, guild-settings and sheet-import suites, lint and typecheck; open PR #423.

## Out of scope

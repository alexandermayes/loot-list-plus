# Quick 261013-w28: addon exports merge every approved list (GH #355 item 1)

## Objective
A raider with approved lists for two phases sees every listed item in game. `buildMemberRankedItems` merges a raider's approved lists instead of letting the last one win, and both export routes (`GET /api/addon/export-string`, `GET /api/addon/guild-data`) pass only lists in the exported expansion. Wire format, key names and the `LLP1:1:` prefix do not change.

## Context (verified at origin/main 24a805a0)
- Work only in `/Users/alexander.mayes/Code/personal/loot-list-plus-wt-355` (WT below). `node_modules` is a symlink to the primary install.
- `lib/addon/member-ranked-items.ts`: `entriesByCharacter.set(sub.character_id, entries)` makes the last list win; the header paragraph "Today's behaviour is kept ... (N-1)" documents it; test M7 pins it.
- Best rank is the HIGHEST rank number. Output goes rank ascending (best last) because readers keep the last entry per item, and `pickReceivedEntries` sorts `b.rank - a.rank` (M3: one award of 20928 drops rank 50, keeps 30). The merge keeps the highest rank.
- One list may hold the same wowhead id in the same slot twice, and both must survive: M2 pins 20928 at 50 and 30, both slot 1, on one list; `domain/loot/apply-receive-skip.ts` documents multi-raid items (Nether Vortex 30183, SSC + TK) ranked twice as two wants. So dedupe across lists only.
- `loot_submissions.expansion_id` is nullable (baseline schema, never made NOT NULL) and the UNIQUE (character_id, guild_id, expansion_id, phase) treats NULLs as distinct. Current writers (`app/contexts/LootListContext.tsx` upserts ~780 and ~908) always set it, but `GET /api/loot-submissions` still has a legacy `tier_id` lookup, so null-expansion approved rows may exist and are exported today. Decision: filter in code and keep null-expansion rows. A SQL `.eq('expansion_id', id)` would silently drop them.
- guild-data: approved lists query ~84-87; active expansion is `guild.active_expansion_id` (its raid_tiers query uses it). export-string: query ~161-171; use `expansionId` (what its raid_tiers query uses, including the `get_guild_expansions` RPC fallback); `stats.submissions` (~286-290) counts `submissions` whose character is exported.
- Route test fakes (`makeClient` in both `__tests__/route.test.ts`) record `.eq` filters into `calls[].filters`, return `loot_submissions` rows filtered by guild_id only, and `rpc` returns `[]`. `Fixture.guilds[].active_expansion_id` is typed `string`. X2 (`stats.submissions` 1) is unaffected: its rows carry no expansion_id.

```ts
interface Entry { key: string; wowhead_id: number; rank: number; slot: number | null; seq: number } // seq: read order, breaks ties
const bestFirst = (a: Entry, b: Entry) => b.rank - a.rank || a.seq - b.seq

// in buildMemberRankedItems:
const mergedByCharacter = new Map<string, Map<string, Entry[]>>() // characterId -> `${wowhead_id}:${slot ?? 1}` -> entries
let seq = 0
for (const sub of submissions) {
  if (!sub.loot_submission_items) continue
  const thisList = new Map<string, Entry[]>()
  for (const item of sub.loot_submission_items) {
    // same removed_at / loot_items / wowhead_id guards as today
    const slot = item.slot ?? null
    const itemSlot = `${wowheadId}:${slot ?? 1}`
    thisList.set(itemSlot, [...(thisList.get(itemSlot) ?? []), { key: `${sub.character_id}-${wowheadId}`, wowhead_id: wowheadId, rank: item.rank, slot, seq: seq++ }])
  }
  let merged = mergedByCharacter.get(sub.character_id)
  if (!merged) {
    merged = new Map()
    mergedByCharacter.set(sub.character_id, merged)
  }
  for (const [itemSlot, listed] of thisList) {
    const before = merged.get(itemSlot) ?? []
    merged.set(itemSlot, [...before, ...listed].sort(bestFirst).slice(0, Math.max(before.length, listed.length)))
  }
}
```

```ts
/** Keeps the lists an export sends: the export's expansion plus lists with no expansion_id (nullable column, legacy rows went out before). No expansion keeps every list. */
export function inExportExpansion<T extends { expansion_id?: string | null }>(submissions: readonly T[], expansionId: string | null | undefined): T[] {
  if (!expansionId) return submissions.slice()
  return submissions.filter(s => s.expansion_id == null || s.expansion_id === expansionId)
}
```

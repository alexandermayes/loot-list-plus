# Quick 261013-w28: Addon exports merge every approved list a raider has (GH #355 item 1)

The addon export routes used to keep only the last approved submission per raider that the query happened to return, so a raider with approved lists for two phases showed only one of them in game. The exports now merge every approved list the raider has in the active expansion.

## Commits (branch fix/355-export-merge-approved-lists, PR #412)

- `1576ff39` fix(addon): exports merge every approved list a raider has in the active expansion (GH #355)

## What changed

- `lib/addon/member-ranked-items.ts`: `buildMemberRankedItems` merges a raider's lists instead of replacing. Per wowhead id and slot it keeps as many entries as the largest single list had, best ranks first (a higher rank number is the better rank), with a read-order tie-break so the existing ordering is stable. Entries within one list are never deduped (an item that drops in two raids can be two wants). New `inExportExpansion(submissions, expansionId)` keeps lists whose `expansion_id` matches or is null; with no active expansion it keeps everything.
- `export-string` and `guild-data` routes: select `expansion_id` and pass the lists through `inExportExpansion` (export-string with its resolved `expansionId`, guild-data with `guild.active_expansion_id`). The SQL filters stay `guild_id` and `status`, so legacy rows with a null `expansion_id` still go out.
- Wire format, key names and the `LLP1:1:` prefix are unchanged.

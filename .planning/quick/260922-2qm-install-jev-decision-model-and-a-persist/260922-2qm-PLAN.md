<objective>
Install the Jev decision model as a reusable skill, and a persistent, off-by-default router that sizes each message and names the smallest capable model tier.

Purpose: Jev is a System One decision model. It never writes text, it answers typed questions about a state in roughly 0.3 seconds for a fraction of a cent, and it is explicitly weak at writing, chat, reasoning, counting, maths and dates. The governing rule is **Jev decides, Claude writes.** Two things are being built on that: a skill so the developer can say "use Jev to sort these" about any pile of text, and a Level 1 router that asks Jev which tier a message needs.

The router carries a real privacy cost. While it is ON, message text leaves the machine for a third party, and the messages in this repository routinely contain guild data, Stripe identifiers and schema. That is why OFF is the default, why OFF is the direction every failure falls towards, and why the skill states the tradeoff in plain words rather than burying it.

Output: a `jev` skill, a `/jev` slash command with on, off and status, a `UserPromptSubmit` hook that advises a tier, four helper agents each pinned to one model, and one command the developer runs themselves to watch Jev answer for real.
</objective>

`readState()` is the single chokepoint that decides whether the router runs, so it fails closed and never throws. It returns a fully formed object every time. Start from the safe shape `{ on: false, tiers: { haiku: 0, sonnet: 0, opus: 0, fable: 0 }, cost: 0, lastField: null }` and only depart from it for values it fully understands. Read `.claude/jev/state.json`; if the file is missing, unreadable, a directory, empty, or does not parse as JSON, return the safe shape. Parse succeeded but the result is not a plain object, return the safe shape. Then set `on` true **only if the parsed `on` is the literal boolean `true`**, so the string `"true"`, `1` and `"yes"` all read as OFF. Copy each tier count only when it is a finite non-negative number, likewise `cost`. Wrap the whole body in try/catch returning the safe shape, so a permissions error or a symlink loop cannot produce an ON.

`writeState(next)` writes atomically: `mkdir` the directory recursively, write to a sibling temp path, then rename over `state.json`. Return true on success and false on any failure, catching everything. It must never throw, because the router calls it on a path where throwing would surface an error to the developer mid-message.

`setOn(value)` is deliberately **not** read-then-write. Turning OFF must succeed when reading is exactly what is broken. Call `readState()` for the counters, which already degrades to zeros rather than failing, then write a fresh object with `on` set to the boolean passed in. A read failure costs the counters, never the ability to turn OFF.

<objective>
Fix GH #276: Classic set pieces (and every other class-locked drop) are offered to classes that cannot use them. The raider item picker (`fetchFilteredLootItems` in `lib/loot-items-query.ts`) filters non-token items by armor and weapon proficiency only; `canWearArmorType` allows lighter armor, so Arcanist (Mage) cloth shows to all nine Classic classes and Gloves of the Redeemed Prophecy (Paladin plate) shows to Warriors.

Approach (OD-1, filter in code): generate `data/item-class-restrictions.ts` from the `wow-classic-items` package's `Classes:` tooltip line for every Classic, TBC and Wrath catalog id, add a pure rule `canClassUseItem` in `domain/loot/`, and consult it in the picker next to `canClassUseToken`. No migration, no seed, no backfill: `loot_items` rows are copied per guild by the expansion seeder, so a `loot_item_classes` seed would need a backfill migration for every existing guild plus the GH-273/284 two-PR deploy ordering, and those rows also mean "officer-allocated to a bracket" (`is_allocated`, `spec_type`), so seeding 191 items there would silently change bracket behaviour. The code rule ships to every guild on deploy and stays a tested pure function, the same way armor and weapon proficiency are enforced today.

Purpose: raiders stop ranking gear they can never equip, officers stop seeing those rankings in the master sheet.
Output: generator script, generated map, domain rule, picker integration, tests, one PR.
</objective>

## Owner decisions (defaults chosen; call out in the PR body)

- OD-1 Filter in code, not `loot_item_classes` seeding. Trade-off: seeding would let the officer UI show the lock as an allocation and would persist if the catalog ever stopped being the source, but it needs a migration plus backfill per guild, a two-PR deploy order, and changes bracket semantics for 191 items. Code rule: zero data change, pure function, tests against the package, consistent with the armor and weapon rules.
- OD-2 Scope is every expansion the package covers (Classic, TBC, Wrath), not Classic only. Same generator cost, and TBC/Wrath have class trinkets and class rings with the same bug.
- OD-3 Tokens stay on `TOKEN_CLASS_MAPPING` (it also covers Cata and MoP, and the completeness suite already checks Classic token lists against the package). The map excludes slot Token.
- OD-4 Recipes excluded from the map to honour GH-284 D-03 ("every class sees every recipe"). Alternative if the owner prefers in-game accuracy: drop the Recipe exclusion and change the GH-284 suite's expected set for the one Warlock pattern. Not done here.
- OD-5 Quest, Book, Trinket, Finger and other class-agnostic-slot items with a `Classes:` line are locked (this is the "other class-locked items" half of #276).
- OD-6 Dragonstalker's Greaves becomes Hunter only; #388 fixed the armor guess, #276 adds the class lock. Documented in the test.
- Unknown or null `wowhead_id`, or a character with no class, is never hidden by the new rule (same stance as `canClassUseToken`: a wrong hide costs a raider a legitimate item; a wrong show is today's behaviour).

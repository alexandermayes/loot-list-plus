## What changed

- `scripts/generate-item-class-restrictions.ts` (npm run classes:gen) reads the `Classes: A, B` tooltip line in `wow-classic-items` for every non-token catalog item and writes `data/item-class-restrictions.ts` (207 entries: 174 Classic, 13 TBC, 20 Wrath). Byte-identical on re-run; the refresh-item-data workflow regenerates it alongside icons and unique flags.
- `domain/loot/class-restrictions.ts` exports pure `canClassUseItem`; unknown ids and null classes are never hidden, mirroring `canClassUseToken`.
- `fetchFilteredLootItems` consults it right after the token branch and before the class-agnostic-slot early return (MC class trinkets, Naxx class rings and similar are class-locked too). `// regression for #276` sits there.
- Filter in code, not `loot_item_classes` rows: `loot_items` is per guild, so seeding needed a backfill per guild and those rows also mean "officer-allocated to a bracket". The code rule reaches every guild on deploy with no data change.

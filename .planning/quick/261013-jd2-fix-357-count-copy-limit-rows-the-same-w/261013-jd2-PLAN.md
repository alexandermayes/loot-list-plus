<objective>
Fix GH #357: the loot list page and POST /api/loot-submissions/submit disagree about which rows count toward copy limits and bracket rules, and the domain scoring default for single_raider_overall_bonus disagrees with the database.

The page only receives loot items from raid tiers with is_guild_active = true (resolveTierIdsForPhases in lib/loot-items-query.ts filters on it), so a saved row for an item from a turned-off tier shows as an empty slot and is not counted. The submit route counts every non-removed row, so a raider can be blocked with a 422 they cannot see or fix. The fix is server-side only (no migration, no page change): the route pulls the tier flag through its existing item join and skips rows whose tier flag is exactly false before both validators. Separately, DEFAULT_SETTINGS.single_raider_overall_bonus moves from false to true to match the guild_settings column default (baseline schema) and the settings GET fallback (app/api/guild-settings/route.ts).

Purpose: a raider is only ever blocked by rows they can see and fix, and scoring defaults agree with the stored default.
Output: tier-aware validation in the submit route with tests, and an aligned scoring default with a pinning test. Two commits on branch fix/357-copy-limit-tiers in the worktree.
</objective>

<objective>
Prove the whole case-study architecture end to end on one dev-only fixture entry: a committed, typed case-study registry feeding a dynamic `/customers/[slug]` route that renders the outcome H1, the lead, and the reused quote block, with correct metadata, correct structured data, and a production build that emits no case-study URL at all.

**As an** officer who lands on a LootList+ customer story from a search result, **I want to** see straight away which guild this is, what changed for them, and how that claim was verified, **so that** I can judge whether the same system would work for my roster.

Purpose: the dynamic-route-plus-data-module shape (D-01) is the only genuinely new architecture in this phase; no public page in this repo uses `generateStaticParams` today. Proving it end to end on the first commit means a wrong turn costs one commit, not five. The same slice also establishes the two hard safety properties everything else in the phase depends on: guild content lives only in the registry, and an empty registry means an unreachable route.

Output: a working, tested case-study template that renders a fixture under `npm run dev` and under vitest, and that a production build refuses to emit.
</objective>

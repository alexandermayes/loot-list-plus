<objective>
Make each post's two public statements about its own freshness agree, and pin them both to the one file that holds the answer.

**As a** search engine reading both a post's structured data and the sitemap, **I want to** be told the same modification date by both, **so that** neither signal contradicts the other and I do not have to guess which one is stale.

Purpose: the sitemap now reads every date from the module, but a post's JSON-LD still carries its own copy. CONTEXT.md deliberately defers consolidating those copies, which means the only thing keeping them equal from here on is a test. This plan writes that test, over all nine posts with no exemption, and bumps the copies for the guides whose content actually changed.

Output: `app/__tests__/blog-dates.test.tsx` as the parity gate, and the linked guides' structured data agreeing with their sitemap entries.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| dates module → per-post structured data | Two independently editable copies of the same public claim, kept equal only by a test |
| post structured data → search engines | `dateModified` and the sitemap `lastmod` are two public statements about the same fact; a disagreement is a contradiction a crawler has to resolve by guessing |
| authorship date → readers | `datePublished` is a claim about when a piece was written, and moving it is a different kind of untruth from a stale modification date |

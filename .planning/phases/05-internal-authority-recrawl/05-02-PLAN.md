<objective>
Build the record and the diagnostic that make the one-shot recrawl safe: a single append-only log that can answer "has this URL already been asked for" mechanically, and a Search Console inspection caller that reports what Google actually thinks of a URL.

**As the** person who will click Request indexing, **I want to** run one command and be told whether a URL was already submitted and what Google currently sees, **so that** I never spend the one request twice and never spend it on a page Google cannot index.

Purpose: the recrawl budget is one request per URL and there is no undo. Today that discipline lives in prose across two runbook paragraphs. This plan turns it into a file plus two commands, and collapses the second record `04-PUBLISH-RUNBOOK.md` was going to keep into a pointer at the first, so there is exactly one place to check.

Output: `scripts/analytics/RECRAWL-LOG.md`, `log-recrawl.py`, `inspect-url.py`, their tests, and a runbook step 5 that points at the log instead of duplicating it.
</objective>

    `validate_row` runs before anything is written and rejects a row missing or blank in `url`, `deploy_sha` or `probe_result`, naming the field. It also rejects a `url` that is not absolute and http or https, and a `request_date` that is present but not an ISO `YYYY-MM-DD` date. A prepared event legitimately has an empty `request_date` and an empty `requester`; a requested event must carry both. Validate before touching the file, so a bad invocation cannot leave a half-written line behind.

    `append_row` creates the parent directory with `os.makedirs(..., exist_ok=True)`, writes the header block and the table header row only when the file does not exist or is zero bytes, then appends one Markdown table row. Never assemble a line by naive concatenation of unescaped values, for the same reason `log-ai-answer.py`'s docstring warns against joining on a comma. Open the file in append mode; never read the whole file, rewrite it, and write it back.

    `read_rows` parses the existing table rows in file order and returns them unchanged. It never sorts, deduplicates, reorders or normalizes. Its docstring says so, matching the sibling.

    `already_requested(url, rows)` returns True when any row for that URL carries a non-empty `request_date`. This is the guard that makes the one-request rule mechanical. `append_row` calls it before appending a requested event and refuses with a non-zero exit that names the URL and the date it was previously requested. Refusing loudly is the whole point: a silent no-op would look like success and a second submission would look like a first.

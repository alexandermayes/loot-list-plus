# Phase 02 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This phase is a copy-and-metadata phase, not a new-UI phase (per 02-RESEARCH.md). No new components, no new visual language, and no new shadcn primitives are introduced. This contract's job is to (a) pin down the *new* visual elements this phase does add — testimonial metadata lines and the verification-line variants — using patterns already shipped in the touched files, and (b) hold the line against scope creep into a redesign. Nothing below overrides CONTEXT.md's D-01 through D-16; where this contract adds a visual default not covered by a locked decision, it is marked "default" and rides on the same D-16 consolidated sign-off checkpoint as the copy itself.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between stacked metadata lines within one testimonial's attribution block (new, this phase) |
| sm | 8px | `mt-2` gap already used below LoginPage's terms paragraph; gap between CTA and secondary link |
| md | 16px | `gap-4` between StatCard/QuoteCard columns; default inter-element spacing |
| lg | 24px | `px-6` / `p-6` section and card padding at mobile breakpoint |
| xl | 32px | — (not used by files this phase touches; listed for completeness) |
| 2xl | 48px | `p-12` QuoteCard padding at `md:` breakpoint |
| 3xl | 64px | — (not used by files this phase touches; listed for completeness) |

**Exceptions (pre-existing, inherited — not introduced by this phase):**
- `mt-5` (20px) — gap between quote text and the author block in `QuoteCard`. Kept as-is; this phase nests new content *inside* that existing 20px-separated block rather than adding a new gap.
- `gap-2.5` (10px) — LoginPage's CTA/secondary-link stack (`flex flex-col gap-2.5`). Kept as-is.
- `p-20` (80px) — QuoteCard padding at `lg:` breakpoint. Kept as-is.

**New exception for this phase:** the metadata block being added inside `QuoteCard` (role, guild, expansion/tier, date, verification line) uses **4px** (`space-y-1`) between its own lines — tighter than the 20px gap that separates the quote from the attribution block — so the new lines read as one grouped unit, not as additional independent sections. This is a default, not a locked decision; confirm at the D-16 sign-off if it looks visually noisy once real metadata is filled in.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Heading | 32px / 42px (`lg:`) | 700 (bold) | 1.02 |
| Body | 16px | 500 (medium) | 1.5 (normal) |
| Label | 13px | 600 (semibold) | 1.2 (tight) |
| Meta | 12px | 400 (regular) | ~1.4 (tight) |

**Where each role is used in this phase:**
- **Heading** — `LoginPage.tsx` H1 only. COPY-01 replaces the *text* ("Epic loot deserves an epic system." → the sign-off-approved voice-adapted draft, starting from the plan's "Set up fair loot in minutes."); the size/weight/line-height classes (`text-[32px] lg:text-[42px] font-bold leading-[1.02]`) do not change. **Do not confuse this with the marketing homepage's H1** in `LandingHero.tsx` ("Epic loot" + shimmer span) — that one is a different file, is D-10's "sacred, does not change" H1, and this phase never touches it.
- **Body** — `LoginPage.tsx` intro paragraph; `QuoteCard`'s quote text (unchanged by this phase).
- **Label** — `QuoteCard`'s author name line (unchanged shape, existing weight/size); reuse for the new metadata block's most prominent line if role/guild is emphasized.
- **Meta** — `QuoteCard`'s existing guild line, extended with the new role / expansion-tier / interview-date / verification-line rows. Also matches `LoginPage.tsx`'s terms-and-privacy footer text.

**Note on weight count:** the template guidance caps a design contract at 2 declared weights. This existing codebase already ships 4 (400/500/600/700) across the roles above, established before this phase and used consistently by role (heading=bold, body=medium, label=semibold, meta=regular). Re-typesetting the marketing surface is out of scope for a copy-only phase — this contract documents the existing per-role weights rather than inventing new ones, so the new metadata lines match what's already on the page.

Ran via the ui-consideration-probe engine over 5 elements (E1 `QuoteCard` metadata block, E2 verification line, E3 `StatCard` replacement label, E4 LoginPage signup copy surface, E5 secondary link). Element kinds (data-display, action-surface, text-link) confirmed as detected — none missed.

Applicable state considerations: 30 total — 10 resolved (explicit), 4 resolved (backstop), 15 dismissed (not applicable to static content), 1 unresolved.

**E1 — `QuoteCard` metadata block (role / guild / expansion-tier / date / verification line):**

| Category | Status | Resolution / Reason |
|----------|--------|---------------------|
| empty | ✅ dismissed | Static hardcoded testimonial content; D-02 guarantees every quote always has at least name+guild attribution already true on the page today — an empty metadata block is not possible. |
| loading | ✅ dismissed | Testimonials are hardcoded JSX, not fetched at runtime; no loading state exists or is introduced. |
| error | ✅ dismissed | No data fetch occurs for testimonial content; static content cannot error. |
| populated | ✅ resolved (explicit) | Normal state: role, guild, expansion/tier, interview date, and one verification-line variant render as a 4px-spaced (`space-y-1`) meta-text stack beneath the quote and author name, per D-02/D-03/D-04. |
| partial | ✅ resolved (explicit) | When a quote's metadata fields are unavailable, only the attribution already true on the page today (name + guild) is kept — no invented or approximated fields (D-02). |
| overflow | ⚠ unresolved — planner must treat as assumption | `QuoteCard`'s fixed-height card (`h-[250px]` mobile / `h-[300px]` desktop) has not been measured against the new 3-5 line metadata block. Today it holds a 2-line attribution block (name + guild) comfortably below the longest existing quote (~230 characters); adding role, expansion/tier, date, and a verification line may exceed that fixed height at the smallest breakpoint. Executor must verify visually per quote once real metadata is filled in at the D-02 checkpoint; if it overflows, combine fields onto shared lines (e.g., "Officer · Crucible · MoP") or increase card height — left to executor/planner judgment, not pre-decided, since it depends on approved metadata length. |
| zero-one-many | ✅ resolved (explicit) | Exactly 5 testimonial quotes are hardcoded on the page; each renders its own independent metadata block — a fixed, known-at-authoring-time count, not a dynamic list, so no zero-state or unbounded-many case exists. |
| long-text | 🧪 resolved (backstop) | The existing meta-text guild line already wraps within the card's fixed width today; new metadata lines reuse the same text style and are expected to wrap the same way. Visual spot-check at execution once real metadata is filled in, not a redesign. |

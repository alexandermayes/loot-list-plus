# Phase 3 — UI Design Contract

> Visual and interaction contract for `/research/wow-classic-loot-systems-2026`.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Scope note: this phase is a single static, build-time-rendered content page (D-05 — the
> page imports a committed JSON artifact at build time; there is no client-side data fetch,
> no form, and no destructive action). The contract below is scoped accordingly — several
> template rows are explicitly marked "not applicable" with the reason stated, per D-09

## Spacing Scale

Declared values (must be multiples of 4 — matches the site-wide scale already in `tailwind.config.js`):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps in the download-links row |
| sm | 8px | Gap between byline meta items (`gap-4` uses 16, but inline `&middot;` separators sit at 8px) |
| md | 16px | Paragraph-to-paragraph spacing inside a finding (`mb-4`), stat-callout internal padding |
| lg | 24px | Space between a finding's number sentence and its data table |
| xl | 32px | Space between H2 finding sections is inherited from prose (`[&_h2]:mt-12`) — see exception below |
| 2xl | 48px | Header block bottom margin (`mb-12`, matches existing blog pattern) |

Exceptions:
- `pt-32` (128px) top padding and `pb-20` (80px) bottom padding on the `<article>` wrapper — inherited verbatim from `app/blog/*/page.tsx` (D-08 requires mirroring this layout exactly); both are still multiples of 4.
- `[&_h2]:mt-12` (48px) between findings is the existing blog `prose` override; not a new value introduced by this phase.
- The inline contextual CTA box (new to this page, not present in blog posts) uses `p-8` (32px) internal padding and `my-12` (48px) vertical margin — both on-scale.

## Typography

Reuses the site's existing `fontSize` scale (`tailwind.config.js`) — no new sizes or weights are introduced.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label (eyebrow tag, byline, breadcrumb, table headers, methodology captions, download-link text) | 12px (`text-sm`) | 400 regular (byline/breadcrumb) — see exception | 1.5 |
| Body (opening copy, finding number-sentence + officer-meaning + limits paragraphs, methodology prose) | 16px (`text-lg`) | 400 regular | 1.5 |
| Heading (H2 per-finding claim) | 20px (`text-2xl`) | 700 bold | 1.2 |
| Display (H1 page title; also the stat-callout big number, at the wide end of this range) | 24px mobile → 32px desktop (`text-3xl md:text-4xl`) for H1; up to 42px (`text-5xl`) for stat-callout numbers only | 700 bold | 1.2 (H1) / 1.02 (stat number, `text-5xl` token) |

Declared weights: **2** — 400 (regular, all body/meta text) and 700 (bold, all headings, the stat-callout number, and the CTA button label).

Exception (inherited, not introduced by this phase): the existing blog header pattern this page mirrors (D-08) uses `font-medium` (500) on the eyebrow tag (e.g. "Guide") and `font-semibold` (600) on H3 subheads and the byline name. This report page has no H3s and no eyebrow-tag emphasis need beyond the label weight above, so it does not need to reproduce those two extra weights — but if a future edit adds an H3 or an eyebrow tag to match blog styling exactly, treat 500/600 as an accepted carry-over from the shared blog pattern rather than a new addition requiring re-approval.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **Heading:** "See how the same rules work with your roster." **Body:** "Create a free guild, import your raiders, and compare the priority order before your next raid night." **Button label:** "Create your guild free" — locked verbatim from the sprint plan's exact template (RESEARCH.md, "Sprint plan exact copy"). Still subject to the cross-phase copy sign-off gate (ROADMAP.md "Copy sign-off is a hard gate... applies to the visible copy in Phases 3 and 4 as well") before ship — plan copy is a starting point, not final text. |
| Empty state | **Not applicable.** The page has no runtime data-fetch path (D-05 — content is a build-time `import` of a committed JSON artifact). There is no "zero findings" runtime state to design: EVID-01 requires ≥3 findings before the page may ship at all, and D-01's human checkpoint is the gate that prevents an under-populated page from ever reaching the page component. If the checkpoint cannot clear 3 findings, the fix is "don't ship yet," not a UI empty state. |
| Error state | **Not applicable**, same reasoning — no client-side fetch, no form submission, nothing that can fail at request time. The CSV/JSON download links point to static files; a broken link is a deploy defect (caught by the EVID-02 manual reproduction check), not a designed UI error state. |
| Destructive confirmation | **Not applicable.** No destructive action exists on this page (no delete, no irreversible user-triggered mutation). The only interactive elements are the CTA link/button and the two download links, both non-destructive. |

## UI Considerations

Applicable state considerations resolved: 5 covered, 0 backstop, 0 unresolved (3 categories dismissed as not applicable to a build-time-only static page).

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Findings list (H2 sections), per-finding data table | ✅ covered | Dismissed as a runtime concern — the page has no data-fetch path; content is baked in at build time from the committed JSON artifact (D-05). The empty case is prevented upstream by the EVID-01 ≥3-findings requirement and the D-01 human checkpoint, not handled by a UI empty-state — see Copywriting Contract "Empty state" row. |
| loading | Findings list, data tables, stat callouts | ✅ covered | Dismissed — Server Component, build-time import, no client fetch; there is no loading transition to design (Standard Stack, Architecture Patterns confirm no runtime DB call). |
| error | Data tables, CSV/JSON download links | ✅ covered | Dismissed for the report content (no fetch to fail). Download links are static files; a 404 is a deploy defect caught by the EVID-02 manual reproduction check, not a UI failure state to render. |
| populated | Findings list, per-finding data table, stat callout | ✅ covered | The only real state. Typical volume: 3-5 H2 findings (D-03 cap), each with one number-sentence, one officer-meaning paragraph, one limits paragraph, one stat callout (big number + label), and — where the finding is a segmented breakdown — one HTML table with 2 to ~8 rows (real segments plus an optional "Other" merge row per D-04). Layout: `max-w-3xl` article column (matches D-08's blog-mirror), stat callout as a bordered `bg-background-elevated` box directly under the number-sentence, table directly under the callout. |
| partial | Segmented breakdown tables (e.g. expansion distribution) | ✅ covered | D-04 governs this directly: any segment below the 10-guild floor is merged into a single "Other" row so the table/percentages still sum to (approximately) 100% without ever rendering a suppressed segment's real count. The table visually treats "Other" as a normal row — no distinct styling, no asterisk, no tooltip — since D-04 requires the merge to be invisible as a *privacy* mechanism, not flagged as an anomaly. The methodology section is where the merge rule itself is disclosed in prose, not the table. |
| overflow | Data tables (on narrow viewports), H2 finding headlines (long plain-English claims) | ✅ covered | Tables: wrap each `<table>` in `<div className="-mx-4 sm:mx-0 overflow-x-auto">`, the exact convention already used for data-dense tables elsewhere in the app (`AttendanceContent.tsx`, `BossSection.tsx`, `LootHistoryTab.tsx`) — horizontal scroll on mobile, no columns dropped, no horizontal clipping. H2 headlines: standard `text-2xl` wraps naturally at the `max-w-3xl` column width; no truncation, no `line-clamp` (a truncated claim headline would misrepresent the finding, which the "checkable proof" goal of this phase cannot allow). |
| zero-one-many | Findings list, segmented-breakdown table rows | ✅ covered | Findings: fixed at 3-5 by D-03/EVID-01 — never zero (gated pre-ship, see "empty" row above), never beyond 5 (explicit cap). No singular/plural copy branching needed since the count is fixed prose, not a live-rendered "{n} findings" counter. Table rows: reads correctly from 2 rows (e.g., two expansion buckets) up to ~8 (all tracked expansions + "Other"); no special one-row layout needed since even a 2-row table renders as a normal `<table>`. |
| long-text | Finding paragraphs (officer-meaning, limits), opening copy, methodology prose | ✅ covered | Reuses the existing blog `prose prose-invert prose-lg` treatment (`[&_p]:leading-relaxed`, `mb-4`) verbatim per D-08 — long-form editorial paragraphs wrap naturally at `max-w-3xl`; no truncation or ellipsis anywhere in body copy, since this is long-form reporting text by design, not a UI label with a fixed footprint. |
